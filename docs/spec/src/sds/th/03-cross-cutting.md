# การออกแบบส่วนกลาง {#cross-cutting}

> [!NOTE] เนื้อหาทั้งหมดในบทนี้เป็นข้อเสนอเพื่อการสร้างตาม ADR ที่ยอมรับแล้ว ชื่อคลาส ตาราง และค่าตั้งยังไม่มีอยู่จริง โมดูล `platform` เป็นเจ้าของบริการส่วนใหญ่เหล่านี้ และการออกแบบเต็มอยู่ใน[บท Platform](#plt) บทนี้ระบุกฎที่ทุกโมดูลต้องปฏิบัติ

## ฐานทางกฎหมายและมาตรฐาน {#xc-legal}

| แหล่งที่มา | ใช้กับ | ตอบไว้ที่ |
| --- | --- | --- |
| PDPA 26 | ข้อมูลส่วนบุคคลอ่อนไหวต้องมีฐานทางกฎหมายเฉพาะ | ฟิลด์ในพจนานุกรมข้อมูล ส่วนความเป็นส่วนตัว |
| PDPA 28 | การส่งข้อมูลส่วนบุคคลไปต่างประเทศ | ข้อมูลอยู่ในไทย ส่วน AI gateway |
| PDPA 37 | การแจ้งเหตุละเมิดต่อสำนักงานภายใน 72 ชั่วโมง | Workflow เหตุละเมิด ส่วนความเป็นส่วนตัว |
| PDPA 39 | บันทึกรายการกิจกรรมการประมวลผล | การส่งออก ROPA ส่วนความเป็นส่วนตัว |
| PDPA 40 | หน้าที่ของผู้ประมวลผลข้อมูล | บทบาทผู้ประมวลผล การเข้าถึงของผู้ปฏิบัติการ ส่วนการเข้ารหัส |
| ETA 9, ETA 26 | ลายมือชื่ออิเล็กทรอนิกส์ | ลายเซ็น PAdES, ADR-0011, XC-DAT-009 |
| ETA 12 | การเก็บเอกสารในรูปข้อมูลอิเล็กทรอนิกส์ | เอกสารที่ลงนามไม่ถูกแก้ไข, XC-DAT-010, XC-DAT-011 |
| OWASP ASVS 5.0 | ระดับ 2 ทั้งระบบ ระดับ 3 สำหรับการเงินและการจ่ายเงิน | ADR-0017, บท DevSecOps |
| WCAG 2.1 AA | ทุกหน้าจอ | ADR-0004, ส่วนการเข้าถึง |
| PAdES พร้อม long-term validation | เอกสารที่ลงนาม | ADR-0011 |
| OpenID Connect และ SAML | การเข้าสู่ระบบ | ADR-0006 |
| RFC 9457 Problem Details | ข้อผิดพลาดของ API | ส่วนรูปแบบข้อผิดพลาด |

> [!LAW] เลขมาตราข้างต้นอยู่ในทะเบียนข้อกฎหมาย ทนายความด้าน PDPA ต้องยืนยันมาตราของ PDPA และผู้ทบทวนกฎหมายต้องยืนยันมาตราของ ETA (OI-XC-05, OI-XC-10) ADR-0014 ยอมรับแล้วโดยรอการทบทวนทางกฎหมาย รวมถึงร่างแนวทางของ PDPC ที่รายงานในเดือนกรกฎาคม 2026

> [!OPEN] พ.ร.บ.การรักษาความมั่นคงปลอดภัยไซเบอร์ และ พ.ร.บ.การบริหารงานและการให้บริการภาครัฐผ่านระบบดิจิทัล อาจเกี่ยวข้องกับหน้าที่เมื่อเกิดเหตุ การเก็บบันทึก และการแลกเปลี่ยนข้อมูล บทนี้ไม่อ้างมาตราใด เพราะยังยืนยันไม่ได้ ฝ่ายกฎหมายต้องระบุมาตราที่ใช้บังคับ (DG-XC-04, OI-XC-08)

## ตัวตนและการเข้าสู่ระบบ {#xc-identity}

Keycloak จัดการการเข้าสู่ระบบผ่าน OIDC และ SAML, MFA และสหพันธ์กับไดเรกทอรีของหน่วยงานและ ThaID (ADR-0006) ผู้เช่าใช้ Keycloak Organizations ไม่ใช่หนึ่ง realm ต่อหน่วยงาน Fisko ไม่เก็บรหัสผ่านของผู้ใช้แบบสหพันธ์

{{fig:xc-signin | การเข้าสู่ระบบของเจ้าหน้าที่}}

| รายการ | การออกแบบ | ที่มา |
| --- | --- | --- |
| ขั้นตอนในเบราว์เซอร์ | OIDC authorization code พร้อม PKCE | ข้อเสนอ |
| ผู้เช่าในโทเค็น | claim ของ organization ผู้ใช้สังกัดหนึ่งผู้เช่าต่อหนึ่ง session | ADR-0006 |
| การเก็บโทเค็น | โทเค็นอยู่ในหน่วยความจำเท่านั้น ไม่อยู่ใน browser storage และ refresh token หมุนทุกครั้งที่ใช้ | XC-SEC-014, ข้อเสนอสำหรับการหมุน |
| การตรวจโทเค็น | แอปตรวจลายเซ็น อายุ audience และ organization ทุกคำขอ | ADR-0006 |
| MFA | บังคับกับบัญชีเจ้าหน้าที่ทุกบัญชีด้วยนโยบาย Keycloak | XC-SEC-006 |
| การเข้าสู่ระบบล้มเหลว | Keycloak ล็อกบัญชี 15 นาทีหลังล้มเหลว 5 ครั้งใน 15 นาที (ข้อเสนอ) | XC-SEC-011 |
| หมดเวลาเมื่อไม่ใช้งาน | ค่าเริ่มต้น 30 นาที เป็นค่าตั้งของผู้เช่าในช่วง 5 ถึง 60 นาที เตือนก่อน 5 นาทีพร้อมปุ่มอยู่ในระบบต่อ Keycloak บังคับขีดจำกัด ส่วนคำเตือนทำงานในเบราว์เซอร์ | XC-SEC-007 ถึง XC-SEC-009, prototype `95b-site.js` |
| การออกจากระบบอัตโนมัติ | บันทึกใน Audit log | XC-SEC-010 |
| บัญชีบริการ | OIDC client credentials ราย adapter และรายการเชื่อมต่อ | ข้อเสนอ |
| ผู้ขาย | เส้นทางแยกภายใต้ organization ของผู้ขาย ดู DG-PRC-12 | ADR-0006 |

> [!OPEN] ยังไม่ยืนยันเงื่อนไขการเข้าร่วม ThaID สำหรับผลิตภัณฑ์ SaaS (ADR-0006) กรมการปกครองต้องยืนยัน บทการเชื่อมโยงระบบมีการออกแบบ adapter

## การอนุญาต {#xc-authorisation}

เซิร์ฟเวอร์เป็นผู้ตัดสินทุกการกระทำ (ADR-0006) การซ่อนปุ่มในเบราว์เซอร์ไม่ใช่การควบคุม

{{fig:xc-authz | ลำดับการตรวจของทุกคำสั่ง}}

- สิทธิ์มีรูปแบบ `<module>.<area>.<verb>` เช่น `prc.plan.write` แต่ละโมดูลกำหนดสิทธิ์ไว้ในบทของตน
- บทบาทจับคู่กับสิทธิ์เป็นข้อมูลของผู้เช่า บทบาทและการจับคู่อยู่ใน `platform` และไม่อยู่ใน Keycloak (ADR-0006)
- `Authorizer` ตรวจสิทธิ์และขอบเขต เช่น หน่วยงานย่อยหรือการเป็นกรรมการ คำขอที่ไม่มีบทบาทใดอนุญาตจะได้ 403 และถูกบันทึก (XC-SEC-004)
- read model ไม่ส่งฟิลด์ที่ผู้เรียกไม่มีสิทธิ์เห็น ไม่ใช้การกรองในเบราว์เซอร์เพื่อการนี้
- สายอนุมัติและเกณฑ์เป็นข้อมูลรายผู้เช่า ขั้นตอนตามกฎหมายอยู่ในโค้ด (ADR-0007)

## การแยกหน้าที่และการมอบอำนาจ {#xc-sod}

กฎการแยกหน้าที่และการมอบอำนาจอยู่ใน `platform` และถูกตรวจทุกการกระทำ (ADR-0006)

- `SodGuard` ทำงานในคำสั่ง หลังการตรวจสิทธิ์และก่อนการเปลี่ยนสถานะ
- ผู้ที่กระทำตามการมอบอำนาจนับเป็นทั้งตนเองและผู้มอบ การมอบอำนาจจึงเลี่ยงกฎการแยกหน้าที่ไม่ได้
- การปฏิเสธบันทึกในธุรกรรมแยก เพื่อให้บันทึกคงอยู่แม้ธุรกรรมหลักย้อนกลับ
- แต่ละโมดูลระบุกฎการแยกหน้าที่ที่ใช้และจุดที่ตรวจ ตามตัวอย่างในบท Procurement
- การมอบอำนาจมีวันเริ่ม วันสิ้นสุด และขอบเขต การใช้จะถูกบันทึกกับการกระทำนั้น

> [!OPEN] SRS ให้ผู้เช่าปิดกฎการแยกหน้าที่ได้ ขณะที่บางกฎอาจมาจากกฎหมาย และ ADR-0007 ไม่ให้ผู้เช่ากำหนดขีดจำกัดทางกฎหมายเอง DG-PRC-05 เก็บคำถามนี้ไว้ให้ผู้เชี่ยวชาญด้านพัสดุและฝ่ายกฎหมาย

## การบังคับแยกผู้เช่า {#xc-tenancy}

ผู้เช่าถูกบังคับหลายชั้น เพื่อให้ความผิดพลาดครั้งเดียวไม่เปิดข้อมูลของผู้เช่าอื่น (ADR-0005, ADR-0013)

{{fig:xc-tenancy | ชั้นการบังคับแยกผู้เช่า}}

| ชั้น | กฎ |
| --- | --- |
| โทเค็น | ผู้เช่ามาจากโทเค็นที่ตรวจแล้ว ไม่ใช่จาก path, body หรือ header |
| `TenantContext` | ตั้งครั้งเดียวต่อคำขอหรืองาน และล้างเมื่อจบ โค้ดเปลี่ยนค่าระหว่างคำขอไม่ได้ |
| ธุรกรรม | ทุกการอ่านและเขียนอยู่ในธุรกรรมที่เริ่มด้วย `SET LOCAL app.tenant_id` ซึ่งเรียกผ่าน `set_config` เพื่อผูกค่าเป็นพารามิเตอร์ได้ |
| Row-level security | เปิดและบังคับทุกตารางของผู้เช่า หากไม่ตั้งค่าจะเกิดข้อผิดพลาด จึงปิดเมื่อล้มเหลว |
| บทบาทฐานข้อมูล | `fisko_app` ไม่มี `BYPASSRLS` และไม่ได้เป็นเจ้าของตาราง migration ใช้บทบาทเจ้าของแยก บทบาท relay เห็นเฉพาะตาราง outbox |
| กุญแจ | กุญแจของผู้เช่าหนึ่งเปิดข้อมูลของอีกผู้เช่าไม่ได้ แม้อยู่ในเซลล์ร่วม |
| การค้นหา | ทุกคำค้นถูกกรองตามผู้เช่าบนเซิร์ฟเวอร์ (ADR-0009) |
| ไฟล์ | key ของวัตถุขึ้นต้นด้วยรหัสผู้เช่า และทุกการดาวน์โหลดผ่านการตรวจสิทธิ์ |
| งานตามกำหนดเวลา | ทำทีละผู้เช่า โดยผูกผู้เช่าเช่นเดียวกับคำขอเว็บ |
| เหตุการณ์และ telemetry | ติดป้ายผู้เช่า ไม่มีข้อมูลส่วนบุคคล |

เนื่องจาก `SET LOCAL` มีผลหนึ่งธุรกรรม การผูกจึงปลอดภัยกับ connection pool แบบ transaction ระเบียนของผู้เช่าอื่นตอบ 404 เพื่อไม่ให้รู้ว่าระเบียนนั้นมีอยู่

`TenantIsolationIT` สร้างจาก schema และพิสูจน์ทุกตารางว่าปฏิเสธการอ่านและเขียนข้ามผู้เช่า (ADR-0005) ตารางใหม่ที่ไม่มี policy จะทำให้ build ล้มเหลว

## การเข้ารหัสและการจัดการกุญแจ {#xc-encryption}

ข้อมูลถูกจัดชั้น และชั้นกำหนดการป้องกัน (ADR-0013)

| ชั้น | ตัวอย่าง | การป้องกัน |
| --- | --- | --- |
| Restricted | เลขประจำตัวประชาชน หนังสือเดินทาง บัญชีธนาคาร ข้อมูลอ่อนไหวตาม PDPA | เข้ารหัสฟิลด์ ปิดบังค่า บันทึกการเปิดดู |
| Confidential | ชื่อ ข้อมูลติดต่อ ซองที่ยังไม่เปิด ผลการประเมิน | การจัดเก็บแบบเข้ารหัส การเข้าถึงตามบทบาท |
| Internal | งบประมาณ แผน ค่าตั้ง | การจัดเก็บแบบเข้ารหัส |
| Public | ผลการจัดซื้อที่เผยแพร่แล้ว | การป้องกันความถูกต้องของข้อมูล |

{{fig:xc-encryption | ลำดับชั้นของกุญแจ}}

| ชั้น | การออกแบบ | ที่มา |
| --- | --- | --- |
| ระหว่างรับส่ง | TLS 1.3 จากเบราว์เซอร์ และ mutual TLS ระหว่างบริการ | ADR-0013 |
| ขณะจัดเก็บ | ฐานข้อมูล สำรองข้อมูล ที่เก็บวัตถุ และดัชนีค้นหาเข้ารหัสด้วยกุญแจ KMS | ADR-0013 |
| ระดับฟิลด์ | `FieldCrypto` ใน `platform`: AES-256-GCM ผ่าน Tink, envelope encryption, กุญแจรายผู้เช่า | ADR-0013 |
| ข้อมูลผูกกับรหัส | ข้อความเข้ารหัสแต่ละค่าผูกกับรหัสผู้เช่า ตาราง และคอลัมน์ ค่าที่คัดลอกไปแถวอื่นจึงถอดรหัสไม่ได้ | ข้อเสนอ |
| Blind index | แฮชแบบมีกุญแจ ใช้กุญแจของตนเอง สำหรับจับคู่ตรงตัวเท่านั้น | ADR-0013 |
| กุญแจที่ห่อแล้ว | keyset ของผู้เช่าเก็บแบบห่อใน schema `platform` และแกะในหน่วยความจำเท่านั้น | ข้อเสนอ |
| การหมุนกุญแจ | อัตโนมัติ กุญแจหลักใหม่เข้ารหัสข้อมูลใหม่ และรุ่นเก่ายังใช้อ่านได้ ระยะที่เสนอ: 12 เดือน | ADR-0013, ข้อเสนอ |
| บันทึกการใช้กุญแจ | ทุกการใช้กุญแจบันทึกเวลา ผู้เช่า รหัสกุญแจ และวัตถุประสงค์ KMS หรือ OpenBao บันทึกการใช้กุญแจหลัก และ `FieldCrypto` บันทึกการใช้กุญแจข้อมูล หนึ่งระเบียนต่อคำขอและวัตถุประสงค์ (ข้อเสนอ) | XC-SEC-023 |
| Bring your own key | กุญแจของหน่วยงานห่อ keyset ของตน หากหน่วยงานเพิกถอน ฟิลด์ Restricted จะอ่านไม่ได้ และหน้าจอแสดงสถานะนั้น | ADR-0013 |
| การติดตั้งเอง | OpenBao ทำหน้าที่แทน KMS ผ่าน port เดียวกัน | ADR-0013 |

กฎของแต่ละฟิลด์ Restricted:

- ฟิลด์เข้าชั้น Restricted ผ่านพจนานุกรมข้อมูลพร้อมเหตุผล ฟิลด์ที่เข้ารหัสเรียงลำดับหรือค้นตามช่วงไม่ได้ จึงต้องเลือกอย่างรอบคอบ (ADR-0013)
- หน้าจอ รายงาน และการส่งออกแสดงค่าที่ปิดบัง การเปิดดูต้องมีบทบาทที่พจนานุกรมข้อมูลอนุญาตและมีเหตุผล และเขียนรายการ Audit (XC-SEC-026, XC-SEC-027, XC-SEC-041)
- ค่า Restricted ไม่เข้าสู่ล็อก เหตุการณ์ การค้นหา หรือการเรียก AI

**ข้อเสนอที่ปิดผนึก** คำตอบที่ปิดผนึกเป็นไปตามส่วนซองเสนอราคาที่ปิดผนึกในบท Procurement โดยมีกุญแจผนึกหนึ่งดอกต่อ RFQ DG-PRC-06 เก็บคำถามที่ค้างเรื่องผู้ปฏิบัติการ

**การเข้าถึงของผู้ปฏิบัติการ** เจ้าหน้าที่ Fisko อ่านข้อมูลผู้เช่าไม่ได้หากไม่มีเหตุผลที่บันทึกและอนุมัติแล้ว (ADR-0013) การเข้าถึงเป็นการให้สิทธิ์แบบจำกัดเวลา อนุมัติโดยบุคคลที่สอง ผู้เช่าเห็นการให้สิทธิ์แต่ละครั้งในมุมมอง Audit ของตน ระยะเวลาที่เสนอคือไม่เกิน 4 ชั่วโมง

> [!WARN] การทำกุญแจหายคือการทำข้อมูลหาย (ADR-0013) การสำรองและกู้คืนกุญแจต้องซ้อมอย่างน้อยทุก 12 เดือน (XC-SEC-031) ตามที่ระบุในบทการติดตั้งและปรับใช้

## ความเป็นส่วนตัวโดยการออกแบบและคุณสมบัติ PDPA {#xc-privacy}

<!-- covers: PDPA 26; PDPA 37; PDPA 39; PDPA 40 -->

การคุ้มครองข้อมูลฝังอยู่ใน `platform` เพื่อให้ทุกโมดูลได้รับไปด้วย (ADR-0014) หน่วยงานเป็นผู้ควบคุมข้อมูล เมื่อ Fisko เป็นแบบโฮสต์ ผู้ให้บริการเป็นผู้ประมวลผลภายใต้ข้อตกลงการประมวลผลข้อมูล สำหรับหน่วยงานที่ติดตั้งเอง ผู้ให้บริการเป็นเพียงผู้จัดหาซอฟต์แวร์

| คุณสมบัติ | การออกแบบ | ที่มา |
| --- | --- | --- |
| พจนานุกรมข้อมูล | ฟิลด์ข้อมูลส่วนบุคคลทุกฟิลด์ระบุชั้น วัตถุประสงค์ ฐานทางกฎหมาย และระยะเก็บ การตรวจใน CI จะล้มเหลวหากฟิลด์ส่วนบุคคลไม่มีรายการ | ADR-0014, ข้อเสนอสำหรับการตรวจ |
| การเก็บเท่าที่จำเป็น | ไม่เก็บฟิลด์ที่ไม่มีวัตถุประสงค์ระบุไว้ | ADR-0014 |
| ฐานทางกฎหมาย | บันทึกตามประเภทข้อมูล แสดงประกาศ และขอความยินยอมเฉพาะเมื่อความยินยอมเป็นฐานที่ถูกต้อง | ADR-0014 |
| Workflow เหตุละเมิด | นาฬิกานับตามขีดจำกัด 72 ชั่วโมงสำหรับแจ้ง PDPC, ขีดจำกัดสูงสุด 15 วันสำหรับการแจ้งล่าช้า, ขั้นแจ้งผู้ได้รับผลกระทบเมื่อความเสี่ยงสูง และการรายงานจากผู้ประมวลผลถึงผู้ควบคุมภายใน 72 ชั่วโมง | ADR-0014, PDPA 37 |
| ประกาศความเป็นส่วนตัว | แสดงที่หน้าเข้าสู่ระบบ พร้อมข้อมูลติดต่อเจ้าหน้าที่คุ้มครองข้อมูลของผู้เช่า | XC-PRV-001, XC-PRV-017 |
| คำขอของเจ้าของข้อมูล | คิวสำหรับการเข้าถึง สำเนา แก้ไข ลบ จำกัด และคัดค้าน พร้อมวันครบกำหนดและหลักฐาน คำขอเข้าถึงครบกำหนดใน 30 วัน OI-XC-06 รอการยืนยันรายการนี้ | XC-PRV-010, XC-PRV-011 |
| บันทึกการประมวลผล | การส่งออก ROPA รายผู้เช่า สำหรับผู้ควบคุมและผู้ประมวลผล | ADR-0014, PDPA 39 |
| ระยะเก็บรักษา | ตารางตามประเภทระเบียน พร้อมการลบหรือทำให้ไม่ระบุตัวตนโดยอัตโนมัติ เป็นงานประจำวัน | ADR-0014 |
| ระเบียนที่กฎหมายให้เก็บ | ประเภทระเบียนแต่ละอย่างระบุกฎ และผู้ขอเห็นเหตุผลที่ลบไม่ได้ | ADR-0014 |
| ข้ามพรมแดน | ข้อมูล สำรองข้อมูล บันทึก และเครื่องมือสนับสนุนอยู่ในไทย | ADR-0014, PDPA 28 |

> [!OPEN] ยังไม่มีระยะเก็บรักษาตามประเภทระเบียน เจ้าของผลิตภัณฑ์ต้องกำหนดร่วมกับกฎเกณฑ์การเก็บรักษาเอกสารที่เกี่ยวข้อง (ADR-0014, DG-XC-05)

## Audit log {#xc-audit}

บันทึกเป็นแบบเพิ่มอย่างเดียวและลูกโซ่แฮชรายผู้เช่า พร้อมจุดตรวจสม่ำเสมอที่เก็บแยก (ADR-0015) รายการเก็บการอ้างอิงบุคคลแบบแฝงนาม ไม่มีรายละเอียดส่วนบุคคล

{{fig:xc-audit | Audit log แบบลูกโซ่แฮชและการลบข้อมูลส่วนบุคคล}}

| รายการ | การออกแบบ | ที่มา |
| --- | --- | --- |
| รายการ Audit | `tenant_id`, `seq`, `at`, `subject_ref`, `role`, `action`, `item_type`, `item_id`, `outcome`, `prev_hash`, `hash` | XC-SEC-032, XC-SEC-037, ข้อเสนอสำหรับคอลัมน์ |
| การเขียน | `CommandAudit` เขียนรายการในธุรกรรมของคำสั่ง การปฏิเสธใช้ธุรกรรมแยก | บท Procurement |
| การร้อยลูกโซ่ | ตัวร้อยรายผู้เช่ากำหนด `seq`, `prev_hash` และ `hash` ตามลำดับ commit ทันทีหลัง commit คำสั่งจึงไม่ต้องต่อคิวบนลูกโซ่ของผู้เช่าในช่วงสูงสุด | ข้อเสนอ |
| แฮช | SHA-256 ของฟิลด์ในรายการและแฮชก่อนหน้า | ข้อเสนอ |
| จุดตรวจ | หัวลูกโซ่ของแต่ละผู้เช่า เขียนลงที่เก็บวัตถุแบบเขียนครั้งเดียวอย่างน้อยทุก 24 ชั่วโมง | XC-SEC-035, ข้อเสนอ |
| การตรวจสอบ | งานประจำวันไล่ลูกโซ่เทียบกับจุดตรวจ รายการที่ถูกแก้ ลบ หรือสลับลำดับจะแจ้งเตือนผู้ตรวจสอบ | XC-SEC-036 |
| เพิ่มอย่างเดียว | `fisko_app` มีสิทธิ์ insert และ select บนตาราง ไม่มี update หรือ delete | ข้อเสนอ |
| การอ่านข้อมูล Restricted | การเปิดดูแต่ละครั้งเขียนรายการ | ADR-0015 |
| เหตุผลและหมายเหตุ | อยู่ในระเบียนธุรกิจ รายการ Audit ชี้ไปยังระเบียนนั้น | บท Procurement |
| ล็อกของแอป | ไม่มีข้อมูลส่วนบุคคล ตรวจด้วยการทดสอบ | ADR-0015 |

**การลบข้อมูล** รายละเอียดส่วนบุคคลอยู่ในตารางบุคคลแยก เข้ารหัสด้วยกุญแจรายบุคคล การลบบุคคลคือการทำลายกุญแจนั้น โดยลูกโซ่ยังสมบูรณ์ รายงานจะแสดงข้อความแทนหลังจากนั้น (ADR-0015)

> [!WARN] กุญแจที่ทำลายแล้วยังคงอยู่ในสำรองข้อมูลรุ่นเก่า ดังนั้นการลบแต่ละครั้งจะบันทึกในรายการลบที่เก็บนอกฐานข้อมูลของเซลล์ด้วย และทุกการกู้คืนจะทำตามรายการนั้นซ้ำก่อนเปิดผู้เช่า รายการนี้เป็นข้อเสนอ และเก็บเฉพาะการอ้างอิงบุคคล

## รูปแบบข้อผิดพลาด {#xc-errors}

ข้อผิดพลาดเป็น RFC 9457 Problem Details แต่ละรายการมี `code` คงที่ และขั้นตอนที่ถูกปฏิเสธจะมีเงื่อนไขแรกที่ไม่ผ่านด้วย ข้อความเป็นภาษาของผู้ใช้

| HTTP | การใช้ | รูปแบบรหัส |
| --- | --- | --- |
| 400 | ฟิลด์ไม่ถูกต้อง ไม่มีเหตุผล | `<MOD>_INVALID_INPUT`, `<MOD>_REASON_REQUIRED` |
| 401 | ไม่มีโทเค็น โทเค็นไม่ถูกต้องหรือหมดอายุ | ไม่มีรหัสของโมดูล |
| 403 | ไม่มีสิทธิ์ ถูกปฏิเสธตามกฎการแยกหน้าที่ คุณสมบัติปิดอยู่ | `<MOD>_FORBIDDEN`, `<MOD>_SOD_BLOCKED`, `<MOD>_FEATURE_OFF` |
| 404 | ไม่มีระเบียน หรือเป็นระเบียนของผู้เช่าอื่น | `<MOD>_NOT_FOUND` |
| 409 | รุ่นไม่ตรง สถานะไม่ถูกต้อง เงื่อนไขไม่ผ่าน | `<MOD>_VERSION_CONFLICT`, `<MOD>_STATE_CONFLICT` |
| 422 | ค่าตั้งนอกช่วง ไฟล์นำเข้าอ่านไม่ได้ | `<MOD>_SETTING_OUT_OF_RANGE`, `<MOD>_IMPORT_INVALID` |
| 429 | จำกัดอัตรา | ไม่มีรหัสของโมดูล |
| 500 | ข้อผิดพลาดที่ไม่คาดคิด เนื้อหามีเพียง `traceId` | ไม่มีรหัสของโมดูล |
| 503 | ผู้เช่าอยู่ระหว่างบำรุงรักษา หรือส่วนที่พึ่งพาใช้งานไม่ได้ พร้อม `Retry-After` | ไม่มีรหัสของโมดูล |

```json
{
  "type": "https://fisko.example/problems/step-check-failed",
  "title": "เงื่อนไขของขั้นตอนนี้ยังไม่ผ่าน",
  "status": 409,
  "code": "PRC_STEP_CHECK_FAILED",
  "firstUnmetCheck": "reference-price",
  "traceId": "4bf92f3577b34da6"
}
```

แต่ละโมดูลระบุรหัสไว้ในบทของตน ข้อความ exception และ stack trace ไม่ถึงผู้เรียก โฮสต์ใน `type` ของตัวอย่างเป็นค่าสมมติ และโฮสต์จริงกำหนดเมื่อเริ่มสร้าง

## ภาษาและการเข้าถึง {#xc-i18n}

- ไทยและอังกฤษผ่านชั้นการแปลเดียว และภาษาไทยเป็นค่าเริ่มต้น (ADR-0004)
- ภาษาของผู้ใช้อยู่ในโปรไฟล์และส่งเป็น `Accept-Language` Fisko เปิดเป็นภาษาไทยเว้นแต่ผู้ใช้เลือกอังกฤษ (XC-ACC-012)
- วันที่และเวลาแสดงและนับตาม Asia/Bangkok และปีงบประมาณนับจาก 1 ตุลาคมถึง 30 กันยายน (XC-ACC-017, XC-ACC-018)
- ข้อมูลธุรกิจมีภาษาเดียว และข้อมูลหลักอาจเก็บทั้งชื่อไทยและอังกฤษ
- การเรียงภาษาไทยใช้ collation ภาษาไทยของ PostgreSQL และการค้นหาภาษาไทยใช้ตัวตัดคำตาม ADR-0009
- หนังสือ แบบฟอร์ม และ PDF เป็นแม่แบบภาษาไทยที่ฝังฟอนต์ TH Sarabun New (ADR-0011)
- WCAG 2.1 AA เป็นข้อกำหนดก่อนปล่อยรุ่น (ADR-0004) Playwright สแกนการเข้าถึงทุกหน้าทั้งสองภาษา และความล้มเหลวจะหยุดการปล่อยรุ่น ทุกรุ่นต้องผ่านการตรวจด้วย screen reader ภาษาไทยโดยคนด้วย (XC-TST-010)

ค่าตั้งของผู้เช่าเปลี่ยนได้เฉพาะในช่วงที่อนุญาต และเซิร์ฟเวอร์ปฏิเสธค่านอกช่วง (ADR-0007) การเปลี่ยนค่าตั้งแต่ละครั้งเขียนรายการ Audit ไม่มีกุญแจหรือความลับในคลังโค้ด (ADR-0013) บท DevSecOps อธิบายการจัดการความลับ

## ความทนทาน {#xc-resilience}

การเรียกออกจากแอปทุกครั้งมี timeout การลองใหม่ใช้กับการเรียกที่ idempotent เท่านั้น พร้อม backoff และ jitter circuit breaker ครอบ adapter ภายนอกแต่ละตัว ตารางแสดงผลของแต่ละความล้มเหลว

| ความล้มเหลว | ผล | ผู้ใช้เห็น |
| --- | --- | --- |
| หนึ่งโซนหรือหนึ่งอินสแตนซ์ | ทราฟฟิกย้ายไปส่วนที่เหลือ | ไม่เห็น หรือลองใหม่ครู่เดียว |
| RabbitMQ | เหตุการณ์รอใน outbox | คำสั่งทำงานได้ ขั้นถัดไปแสดงว่ารอ |
| OpenSearch | ค้นหาไม่ได้ แหล่งข้อมูลจริงไม่กระทบ | การค้นหาแสดงประกาศ และค้นด้วยเลขที่ตรงตัวจาก PostgreSQL ได้ |
| ที่เก็บ S3 หรือ ClamAV | การอัปโหลดรอหรือถูกปฏิเสธ ไฟล์คงกักกันอยู่ | ไฟล์แสดงว่ารอดำเนินการ |
| KMS | กุญแจในแคชใช้ได้ชั่วครู่ จากนั้นฟิลด์ Restricted ใช้งานไม่ได้ | ค่าปิดบังพร้อมประกาศ งานอื่นดำเนินต่อได้ |
| Keycloak | เข้าสู่ระบบใหม่ไม่ได้ โทเค็นที่ยังใช้ได้ทำงานจนหมดอายุ | ประกาศที่หน้าเข้าสู่ระบบ |
| GFMIS, e-GP, อีเมล หรือ SMS หาก OI-PLT-14 อนุญาต | การส่งรอและลองใหม่ | สถานะการส่ง |
| ผู้ให้บริการ AI | เครื่องมือ AI หยุด ทุกคุณสมบัติยังทำงาน (ADR-0016) | เครื่องมือแสดงว่าไม่พร้อมใช้งาน |
| PostgreSQL ตัวหลักในเซลล์หนึ่ง | สลับไปตัวสำรอง กระทบเฉพาะเซลล์นั้น | ข้อผิดพลาดชั่วครู่ แล้วกลับเป็นปกติ |

## การแคช {#xc-caching}

ADR ไม่ได้ระบุผลิตภัณฑ์แคชร่วม แคชจึงอยู่ในโปรเซส และไม่เก็บสิ่งอ่อนไหว ค่า TTL เป็นข้อเสนอ

| สิ่งที่แคช | อยู่ที่ใด | TTL | การทำให้หมดอายุ |
| --- | --- | --- | --- |
| แผนที่ผู้เช่าถึงเซลล์ | หน่วยความจำของ router | 60 วินาที | control plane ส่งเมื่อมีการย้าย |
| กุญแจลงนามของ Keycloak | หน่วยความจำของแอป | 10 นาที | รีเฟรชเมื่อพบ key id ที่ไม่รู้จัก |
| ค่าตั้งของผู้เช่าและชุดกฎตามกฎหมาย | หน่วยความจำของแอป | 5 นาที | เหตุการณ์ `settings.changed` |
| keyset ของผู้เช่าที่แกะแล้ว | หน่วยความจำของแอป | 5 นาที | การหมุนกุญแจ หรือเมื่ออินสแตนซ์หยุด |
| คำแปล design token ไฟล์คงที่ | เบราว์เซอร์และ edge | ตามแฮชของไฟล์ | รุ่นใหม่ |
| ข้อมูลจากเซิร์ฟเวอร์ | TanStack Query ในเบราว์เซอร์ | สั้น ตามแต่ละคำขอ | ล้างเมื่อออกจากระบบ |

การตรวจสิทธิ์และการแยกหน้าที่อ่านข้อมูลปัจจุบันในธุรกรรมเสมอ และไม่แคช คีย์ของแคชขึ้นต้นด้วยรหัสผู้เช่าเสมอ

## การจัดการไฟล์และการสแกน {#xc-files}

Fisko ใช้เฉพาะ S3 API ผ่าน `FileStore` ใน `platform` (ADR-0010) ทุกการอัปโหลดถูกสแกนก่อนจะดาวน์โหลดได้

{{fig:xc-upload | สถานะของไฟล์ที่อัปโหลด}}

- การอัปโหลดผ่านแอป ซึ่งตรวจขนาด ชนิดจากเนื้อหา และสิทธิ์ แล้วเข้ารหัสสตรีมด้วยกุญแจผู้เช่าผ่าน Tink วิธีนี้ทำงานเหมือนกันทุกผลิตภัณฑ์ S3 จึงไม่ใช้ URL อัปโหลดแบบ presigned
- วัตถุเข้า prefix กักกัน เหตุการณ์ใน outbox เริ่มการสแกน และ ClamAV รับสตรีมที่ถอดรหัสแล้วผ่านช่องทางส่วนตัว ไม่มีการจัดเก็บข้อความธรรมดา
- ไฟล์ที่สะอาดย้ายไป prefix สุดท้าย ไฟล์ที่ติดเชื้อถูกปฏิเสธ แจ้งผู้อัปโหลด และเขียนรายการ Audit
- การดาวน์โหลดผ่านการตรวจสิทธิ์ แล้วสตรีมจากแอปด้วย `Content-Disposition: attachment`
- เอกสารที่ลงนามแล้วไม่ถูกแก้ไข การแก้ไขจะสร้างรุ่นใหม่ (ADR-0011)

การทดสอบความเข้ากันได้ทำกับผลิตภัณฑ์ที่เก็บแต่ละตัวที่ระบุในเอกสาร (ADR-0010) ชนิดไฟล์ที่อนุญาตและขนาดสูงสุดเป็นค่าตั้งที่มีช่วง เจ้าของผลิตภัณฑ์ต้องกำหนดขีดจำกัดเหล่านั้น (DG-XC-06)

## AI gateway {#xc-ai}

การเรียก AI ทั้งหมดผ่าน model gateway เดียวใน `platform` (ADR-0016) ไม่มีโมดูลใดเรียกผู้ให้บริการโดยตรง และกฎสถาปัตยกรรมตรวจเรื่องนี้

{{fig:xc-ai | เส้นทางของคำขอ AI}}

- AI ปิดเป็นค่าเริ่มต้น และแต่ละหน่วยงานเลือกเปิดรายเครื่องมือ
- แต่ละหน่วยงานเลือกผู้ให้บริการ รวมถึงโมเดลที่โฮสต์ในไทย
- gateway ลบข้อมูลส่วนบุคคลก่อนส่ง ใช้นโยบายของผู้เช่า และบันทึกทุกการเรียก
- ไม่ส่งข้อมูล Restricted ซองที่ปิดผนึก หรือราคาเสนอที่ยังไม่ประกาศผล
- ผลจาก AI เป็นคำแนะนำ คนเป็นผู้ตัดสินใจทุกครั้ง และมีการบันทึก
- เครื่องมือของโมดูลเป็นรายการปิดรายเอเจนต์ และขั้นที่เขียนข้อมูลจะหยุดรอคน ตามที่บท Procurement แสดง

> [!OPEN] ยังไม่ยืนยันว่ามีโมเดลที่เหมาะสมซึ่งทำงานในไทยทั้งหมดหรือไม่ (ADR-0016) ระหว่างนี้ หน่วยงานที่เปิดใช้ผู้ให้บริการนอกไทยจะเกิดคำถามเรื่องการส่งข้อมูลตาม PDPA 28 หน้าจอเลือกเปิดต้องแสดงสถานที่ที่ผู้ให้บริการประมวลผลคำขอ (XC-AI-009) เจ้าหน้าที่คุ้มครองข้อมูลและเจ้าของผลิตภัณฑ์ต้องตัดสินว่าต้องมีเงื่อนไขใดอีก (DG-XC-07)
