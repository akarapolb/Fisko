# การเชื่อมโยงระบบ {#integration}

> [!NOTE] สัญญาภายนอกส่วนใหญ่ยังไม่ทราบ บทนี้ออกแบบส่วนที่ Fisko ควบคุมได้ คือ port, adapter, การลองใหม่ และสถานะ ชื่อ port และตารางสถานะเป็นข้อเสนอ adapter ใดจะสมมติรูปแบบไม่ได้จนกว่าเจ้าของระบบจะยืนยัน

## หลักการ {#int-principles}

- ตรรกะธุรกิจเห็นเพียง port โดย adapter เป็นผู้ติดตั้ง การเปลี่ยนสัญญาจึงกระทบเฉพาะ adapter
- การเชื่อมโยง GFMIS และ e-GP รันเป็น adapter แยกบนเส้นทาง outbox ลองใหม่อย่างปลอดภัย และแสดงสถานะให้ผู้ใช้เห็น (ADR-0008)
- ไม่มีคำสั่งใดรอระบบภายนอก ความล้มเหลวทำให้งานรอ โดยเห็นสถานะได้
- ระบบภายนอกแต่ละระบบมี adapter จำลองที่ระบุชัดเจน และอยู่เฉพาะในโปรไฟล์ทดสอบ (PRC-NFR-006)
- ข้อมูลรับรองเป็นรายผู้เช่าเท่าที่ระบบภายนอกรองรับ และอยู่ในที่เก็บความลับ
- ทราฟฟิกขาออกไปได้เฉพาะปลายทางที่ระบุของแต่ละ adapter

## เส้นทางขาออก {#int-outbound}

{{fig:int-outbox | Outbox ไปยังระบบภายนอก}}

รายการขาออกแต่ละรายการมีแถวใน `delivery` ใน schema ของโมดูลที่เป็นเจ้าของ adapter ผู้รับบันทึก `eventId` ที่ทำแล้วในตาราง `inbox_event` ในธุรกรรมเดียวกับงาน รายการซ้ำจึงไม่มีผล

| คอลัมน์ | ความหมาย |
| --- | --- |
| `delivery_id` | เป็นคีย์ idempotency ที่ส่งให้ระบบภายนอกด้วย หากระบบนั้นรับ |
| `event_id` | เหตุการณ์ต้นทาง |
| `adapter`, `target_type`, `target_id` | สิ่งที่ส่งและระเบียนที่เกี่ยวข้อง |
| `state` | ดูสถานะด้านล่าง |
| `attempts`, `next_attempt_at` | ตำแหน่งของการลองใหม่ |
| `external_ref` | เลขอ้างอิงที่ระบบภายนอกส่งกลับ |
| `error_code`, `error_text` | ความล้มเหลวล่าสุด ไม่มีข้อมูลส่วนบุคคล |
| `cancelled_by_ref`, `cancel_reason` | ตั้งเมื่อเจ้าหน้าที่ยกเลิก |

การออกแบบเก็บ payload ที่ส่งเป็นการอ้างอิงไฟล์ เมื่อระเบียนต้องมีหลักฐานของสิ่งที่ส่งออก ระยะเก็บไฟล์เหล่านั้นเป็นไปตามตารางระยะเก็บ

## การลองใหม่และสถานะ {#int-status}

{{fig:int-state | สถานะของการส่งออกหนึ่งรายการ}}

| สถานะ | ความหมาย | ผู้ใช้เห็นเป็น |
| --- | --- | --- |
| `pending` | รอ adapter | รอส่ง |
| `sending` | กำลังเรียก | กำลังส่ง |
| `retrying` | ล้มเหลวชั่วคราว มีเวลาลองครั้งถัดไป | จะลองใหม่ตามเวลาที่แสดง |
| `delivered` | ปลายทางรับแล้ว | ส่งแล้ว พร้อมเลขอ้างอิงภายนอก |
| `failed` | ถูกปฏิเสธ หรือครบจำนวนครั้ง | ล้มเหลว พร้อมเหตุผลและงานให้เจ้าหน้าที่ |
| `cancelled` | เจ้าหน้าที่หยุดพร้อมเหตุผล | ยกเลิกแล้ว |

กฎ:

- backoff เป็นข้อเสนอ: 1 นาที 5 นาที 30 นาที 2 ชั่วโมง 6 ชั่วโมง พร้อม jitter แล้วเป็น `failed` แต่ละ adapter กำหนดนโยบายของตนได้
- timeout, การตอบ 5xx และ 429 เป็นความล้มเหลวชั่วคราว การปฏิเสธจากการตรวจข้อมูลเป็นผลสุดท้าย และไป `failed` ทันที
- timeout ไม่ได้พิสูจน์ว่าการเรียกล้มเหลว หากปลายทางไม่มีคีย์ idempotency adapter จะถามสถานะของรายการก่อนเมื่อมีวิธีถาม หากไม่มีทั้งสองอย่าง การส่งจะเป็น `failed` เพื่อให้เจ้าหน้าที่ตรวจ และไม่ส่งซ้ำ
- การส่งซ้ำโดยเจ้าหน้าที่ใช้การส่งเดิมด้วยคีย์เดิม และเขียนรายการ Audit
- circuit breaker หยุดการเรียกระหว่างระบบล่ม รายการรอเป็น `retrying` และการล่มไม่กินจำนวนครั้ง
- ข้อความที่ผู้รับประมวลผลไม่ได้จะย้ายไป dead-letter queue พร้อมการแจ้งเตือน
- งานประจำวันเทียบรายการที่ส่งแล้วกับระเบียนของปลายทาง หากมีแหล่งข้อมูลดังกล่าว

## รายการ Adapter {#int-catalogue}

| ระบบภายนอก | โมดูลเจ้าของ | Port | ทิศทาง | การติดตั้งแรก | สถานะสัญญา |
| --- | --- | --- | --- | --- | --- |
| GFMIS | `finance` | `GfmisGateway` | ขาออกและขาเข้า | ยังเปิดอยู่ | ไม่ทราบ |
| สถานะ e-GP | `procurement` | `EgpStatusSource` | ขาเข้า | `EgpFileAdapter`: ไฟล์ที่เจ้าหน้าที่อัปโหลด | ไม่ทราบ |
| ชุดข้อมูล e-GP | `procurement` | `EgpPackBuilder` | ขาออกด้วยมือ | ข้อความภาษาไทยสำหรับคีย์ | รูปแบบของ Fisko เอง |
| ThaID | `platform` ผ่าน Keycloak | Identity broker | เข้าสู่ระบบ | OIDC broker ใน Keycloak | ยังไม่ยืนยัน |
| ไดเรกทอรีของหน่วยงาน | `platform` ผ่าน Keycloak | Identity broker | เข้าสู่ระบบ | สหพันธ์ OIDC, SAML หรือ LDAP | รายหน่วยงาน |
| อีเมล | `platform` | `Notifier` | ขาออก | SMTP | มาตรฐาน |
| SMS, LINE | `platform` | `MessageChannel` ภายใต้ `Notifier` | ขาออก | ไม่มีจนกว่าจะตัดสิน OI-PLT-14 | ยังเปิดอยู่ (OI-PLT-14, DG-XC-22) |
| ระบบ PM ของหน่วยงาน | `projects` | `ProjectSystemGateway` (ข้อเสนอ) | ขาออก และขาเข้าผ่าน `POST /pm/messages` | มาตรฐานของ Fisko บน REST | ยังไม่มีสัญญา (OI-PRJ-03) รหัสการเชื่อมต่อยังเปิดอยู่ (OI-PRJ-10) |
| ผู้ให้บริการ AI | `platform` | `AiGateway` | ขาออก | ยังเปิดอยู่ รายหน่วยงาน | ต้องเลือกผู้ให้บริการ |
| บริการใบรับรองและประทับเวลา | `platform` | `DocumentService` | ขาออก | ยังเปิดอยู่ | ค้างตาม ADR-0011 |

บท Procurement ระบุ port อื่นของตน ได้แก่ `EntityStatusSource`, `AppealForwarding` และ `OcdsExporter` แต่ละบทโมดูลระบุ adapter ที่ตนเป็นเจ้าของพร้อมข้อกำหนด

## GFMIS {#int-gfmis}

GFMIS อยู่ใน `finance` ส่วน Procurement เห็นเพียงข้อเท็จจริงของใบสั่งซื้อผ่าน `FinanceFacts` และไม่เรียก GFMIS (PRC-IR-009) [บท Finance](#fin) เก็บรายการ การจับคู่ และการกระทบยอด

- `GfmisGateway` รับรายการการเงินและคืนเลขอ้างอิงหรือการปฏิเสธ โดยไม่กล่าวถึงวิธีรับส่ง
- รายการออกจาก outbox เท่านั้น หลังการอนุมัติ ใบสำคัญแสดงสถานะการส่ง
- รายการที่ GFMIS ปฏิเสธไม่เปลี่ยนระเบียนที่อนุมัติแล้วโดยอัตโนมัติ แต่สร้างงานให้เจ้าหน้าที่การเงิน

> [!OPEN] ยังไม่ทราบว่า GFMIS เชื่อมต่ออย่างไร กรมบัญชีกลางต้องให้ข้อมูล: วิธีรับส่ง (ไฟล์ API หรือบริการผ่าน terminal) รูปแบบระเบียน วิธีที่หน่วยงานหรือผู้ให้บริการ SaaS ได้รับสิทธิ์ ตัวตนที่ใช้ส่งรายการ และวิธีรับคำตอบและการปฏิเสธ (ADR-0008, DG-XC-20) หากมีเฉพาะเส้นทางไฟล์ `GfmisGateway` จะสร้างไฟล์ให้เจ้าหน้าที่นำส่ง และสถานะการส่งคงเดิม

## e-GP {#int-egp}

ขั้นตอนจัดซื้อจัดจ้างอย่างเป็นทางการอยู่ใน e-GP (PRC-CR-001) Fisko เตรียม ตรวจ บันทึก และติดตาม ส่วน External adapters ในบท Procurement เก็บการออกแบบ adapter โดยเริ่มจาก adapter แบบไฟล์

> [!OPEN] ยังไม่ทราบสัญญาของ e-GP (OI-PRC-03) กรมบัญชีกลางต้องยืนยันรูปแบบและฟิลด์ของไฟล์ส่งออก การเปิด API ให้หน่วยงาน วิธีให้สิทธิ์ รูปแบบเลขประกาศ และการทำงานของการบริหารสัญญาในระบบนั้น ระหว่างนี้ `EgpFileAdapter` อ่านการจับคู่คอลัมน์ที่ไม่ผูกกับผู้เช่าใดซึ่งเก็บเป็นการตั้งค่า

## ThaID และไดเรกทอรีของหน่วยงาน {#int-identity}

แอป Fisko ไม่คุยกับระบบเหล่านี้โดยตรง Keycloak เป็นตัวกลาง แอปจึงเห็นโทเค็น OIDC เพียงแบบเดียว (ADR-0006)

- หน่วยงานเชื่อมไดเรกทอรีเข้ากับ Organization ของตนใน Keycloak ด้วย OIDC หรือ SAML ส่วนสหพันธ์ LDAP ใช้กับไดเรกทอรีที่ไม่มีทั้งสองอย่าง
- กลุ่มในไดเรกทอรีเสนอบทบาทของ Fisko ได้ และผู้ดูแลหน่วยงานยืนยันบทบาทใน `platform` บทบาทยังอยู่ใน Fisko (ADR-0006)
- ผู้ใช้ที่ถูกลบจากไดเรกทอรีเข้าสู่ระบบไม่ได้อีก งานประจำวันตั้งผู้ใช้เป็นไม่ใช้งานใน `platform` โดยคงระเบียนไว้
- ThaID เป็นผู้ให้บริการตัวตนอีกรายหนึ่ง เปิดราย organization

> [!OPEN] ยังไม่ยืนยันการเข้าร่วม ThaID สำหรับผลิตภัณฑ์ SaaS (ADR-0006) กรมการปกครองต้องระบุว่าผู้ให้บริการ SaaS ลงทะเบียน client เดียวสำหรับหลายหน่วยงานได้หรือไม่ โปรโตคอลและแอตทริบิวต์ที่ส่งกลับ และมีเลขประจำตัวประชาชนหรือไม่ หากมี แอตทริบิวต์นั้นเป็น Restricted และต้องไม่เข้าสู่โทเค็น (DG-XC-21)

> [!OPEN] Keycloak Organizations ต้องผ่าน load test ที่เป้าหมาย 500 ผู้เช่า (ADR-0006) หากไม่ผ่าน ผู้นำทางเทคนิคต้องเสนอ ADR ใหม่ เพราะ ADR-0006 ปฏิเสธแนวทางหนึ่ง realm ต่อหน่วยงานแล้ว

## อีเมลและช่องทางอื่น {#int-notify}

`Notifier` ใน `platform` เป็นทางออกเดียวของการแจ้งเตือน รายละเอียดอยู่ใน[บท Platform](#plt)

- การแจ้งเตือนผ่านเส้นทางการส่งข้างต้น ผู้ใช้จึงเห็นได้ว่าการแจ้งล้มเหลว
- อีเมลใช้ SMTP กับ TLS จึงใช้ผู้ให้บริการใดก็ได้ บริการแบบโฮสต์ใช้ผู้ให้บริการที่เก็บข้อมูลในไทย (ADR-0014) ผู้ติดตั้งเองกำหนด relay ของตน
- โดเมนผู้ส่งมี SPF, DKIM และ DMARC ผู้เช่าแต่ละรายตั้งผู้ส่งของตนภายในโดเมนที่ยืนยันแล้วได้
- ข้อความมาจากแม่แบบของผู้เช่า ในภาษาของผู้ใช้
- ข้อความมีข้อมูลเท่าที่จำเป็น พร้อมลิงก์เข้า Fisko สำหรับส่วนที่เหลือ ช่องทางข้อความ หาก OI-PLT-14 อนุญาต ต้องไม่มีค่า Restricted
- การตีกลับบันทึกในการส่ง ผู้ใช้เลือกช่องทางได้ ยกเว้นการแจ้งที่กฎหมายหรือกฎความมั่นคงปลอดภัยกำหนด

> [!OPEN] เจ้าของผลิตภัณฑ์ต้องเลือกผู้ให้บริการอีเมลที่เก็บข้อมูลในไทย ช่องทางอื่นเป็นคำถามเดียวกันใน OI-PLT-14 และ DG-XC-22 โดยเอกสารออกแบบและโค้ดไม่มี SMS และโค้ดระบุ LINE จะไม่สร้างช่องทางดังกล่าวจนกว่าจะได้คำตอบ

## ผู้ให้บริการ AI {#int-ai}

`AiGateway` มีหนึ่ง adapter ต่อผู้ให้บริการ และนโยบายของผู้เช่าเลือกหนึ่งราย (ADR-0016) บทการออกแบบส่วนกลางระบุกฎ

- ผู้เช่าที่ปิด AI ไม่มีการเรียก AI ขาออก และกฎทราฟฟิกขาออกก็ปิดกั้นด้วย
- adapter ของผู้ให้บริการได้รับข้อความที่ลบข้อมูลส่วนบุคคลแล้ว และไม่ได้รับกุญแจของผู้เช่าหรือค่า Restricted
- การเรียกเป็นแบบทันทีพร้อม timeout ความล้มเหลวแสดงว่าเครื่องมือไม่พร้อมใช้งาน และไม่ใช้เส้นทางการส่ง
- เงื่อนไขของผู้ให้บริการแต่ละรายต้องระบุว่าไม่ฝึกโมเดลด้วยข้อมูลผู้เช่า และระบุสถานที่ประมวลผล

> [!OPEN] ต้องยืนยันว่าโมเดลใดทำงานในไทยทั้งหมด จากหน้าการให้บริการล่าสุดของผู้ให้บริการ (ADR-0016) เจ้าของผลิตภัณฑ์ต้องยืนยันก่อนผู้เช่าใดจะเลือกเปิด
