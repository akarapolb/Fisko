# DevSecOps {#devsecops}

> [!NOTE] เครื่องมือที่ระบุใน ADR-0017, ADR-0012 และ ADR-0001 ตัดสินแล้ว ส่วนเกณฑ์ ลำดับขั้น และเครื่องมือที่ระบุว่าเป็นข้อเสนอยังไม่ตัดสิน คลังโค้ด แพลตฟอร์ม CI และ pipeline ยังไม่มีอยู่จริง

## Pipeline {#dso-pipeline}

pipeline เดียวใช้กับบริการแบบโฮสต์และรุ่นสาธารณะ เพื่อให้บริการแบบโฮสต์รันโค้ดสาธารณะ (ADR-0001)

{{fig:dso-pipeline | สายงาน CI และ CD}}

| ขั้น | ทำงานเมื่อ | วัตถุประสงค์ |
| --- | --- | --- |
| Pull request | ทุกการเปลี่ยนแปลง | สร้าง ทดสอบเร็ว ขอบเขตโมดูล การสแกน |
| สาขาหลัก | ทุก merge | ทดสอบตั้งแต่ต้นจนจบ และสแกนแบบ dynamic |
| รุ่นปล่อย | ทุก release candidate | image, SBOM, ลายเซ็น, ทั้งสองชุดติดตั้ง รุ่นหลักเพิ่ม load test และการทดสอบเจาะระบบ |
| นำไปใช้ | ทุกรุ่นที่อนุมัติ | ทีละเซลล์ผ่าน Argo CD |

pipeline ของรุ่นปล่อยใช้เวลานานขึ้น และการทดสอบเจาะระบบเป็นค่าใช้จ่ายประจำ (ADR-0017) ชุดทดสอบที่ช้าจึงทำงานหลัง merge เพื่อให้ pull request เร็ว

## ประตูคุณภาพ {#dso-gates}

ประตูที่ไม่ผ่านจะหยุดการ merge หรือการปล่อยรุ่น ไม่มีผู้ใดปิดการทดสอบขอบเขตได้ (ADR-0002) ค่าที่ระบุว่าเป็นข้อเสนอต้องได้รับความเห็นชอบจากผู้นำทางเทคนิค

| ประตู | เครื่องมือ | ขั้น | หยุดเมื่อ | ที่มา |
| --- | --- | --- | --- | --- |
| หน่วยทดสอบ | JUnit | Pull request | ไม่ผ่านรายการใด | ADR-0017 |
| ขอบเขตโมดูล | Spring Modulith `verify`, ArchUnit | Pull request | ละเมิดรายการใด | ADR-0002 |
| Integration test | JUnit กับ Testcontainers | Pull request | ไม่ผ่านรายการใด | ADR-0017 |
| Row-level security | `TenantIsolationIT` สร้างจาก schema | Pull request | ตารางไม่มี policy หรือมีการเข้าถึงข้ามผู้เช่า | ADR-0005 |
| การวิเคราะห์แบบ static | SonarQube | Pull request | พบระดับ critical หรือ high ความครอบคลุมโค้ดใหม่ต่ำกว่าร้อยละ 80 (ข้อเสนอ) | XC-DSO-001 |
| สแกน dependency | ตัวสแกน dependency บน Maven และ npm | Pull request | ช่องโหว่ระดับ high หรือ critical ที่มีวิธีแก้ (ข้อเสนอ) | XC-DSO-002 |
| ตรวจใบอนุญาต | ตัวสแกนใบอนุญาต | Pull request | ใบอนุญาตนอกรายการที่อนุญาต | XC-LIC-003 |
| สแกนความลับ | ตัวสแกนความลับ และ pre-commit hook (ข้อเสนอ) | Pull request | พบรายการใด | XC-SEC-030 |
| ข้อมูลส่วนบุคคลในล็อก | การทดสอบตรวจล็อก | Pull request | พบฟิลด์ส่วนบุคคลในล็อกหรือเหตุการณ์ | ADR-0015, ADR-0017 |
| พจนานุกรมข้อมูล | ตรวจเทียบกับ schema | Pull request | ฟิลด์ข้อมูลส่วนบุคคลไม่มีรายการ (ข้อเสนอ) | ADR-0014 |
| ความเข้ากันได้ของ API | เทียบ OpenAPI และ AsyncAPI | Pull request | การเปลี่ยนที่ไม่เข้ากันโดยไม่เพิ่มรุ่น (ข้อเสนอ) | ADR-0003 |
| ตั้งแต่ต้นจนจบ | Playwright ไทยและอังกฤษ | สาขาหลัก | ไม่ผ่านรายการใด | ADR-0004, ADR-0017 |
| การเข้าถึง | สแกนใน Playwright และตรวจด้วย screen reader ภาษาไทยโดยคนในทุกรุ่น | สาขาหลัก รุ่นปล่อย | ไม่ผ่าน WCAG 2.1 AA | XC-TST-010 |
| ปิด AI | รันทุกโมดูลโดยปิด AI | สาขาหลัก | ไม่ผ่านรายการใด | XC-TST-009 |
| สแกนแบบ dynamic | OWASP ZAP | สาขาหลัก | พบระดับ critical หรือ high | XC-DSO-001 |
| Load | k6 ตามช่วงสูงสุดวันที่ 30 กันยายน | ก่อนรุ่นหลักทุกรุ่น | ไม่บรรลุวัตถุประสงค์ที่ปริมาณช่วงสูงสุด | XC-TST-003 |
| ทั้งสองชุดติดตั้ง | ติดตั้งและ smoke test ทั้งเล็กและองค์กร | รุ่นปล่อย | ไม่ผ่านรายการใด | XC-TST-007 |
| ความเข้ากันได้ของที่เก็บ | ทดสอบผลิตภัณฑ์ S3 ที่ระบุในเอกสาร | รุ่นปล่อย | ไม่ผ่านรายการใด | XC-TST-008 |
| ความครอบคลุมข้อกำหนด | รายงานจากชื่อการทดสอบถึงรหัส SRS | รุ่นปล่อย | ข้อกำหนดระดับ Must ไม่มีการทดสอบ (ข้อเสนอ) | ADR-0017 |
| ทดสอบเจาะระบบ | ผู้ทดสอบอิสระ | ก่อนรุ่นหลักทุกรุ่น | มีข้อค้นพบ critical หรือ high ค้างอยู่ | XC-DSO-005 |

ความมั่นคงปลอดภัยยึด OWASP ASVS 5.0: ระดับ 2 ทั้งระบบ และระดับ 3 สำหรับการเงินและการจ่ายเงิน (ADR-0017) รายการตรวจจับคู่ข้อกำหนด ASVS แต่ละข้อกับการทดสอบหรือการทบทวน และแนบไปกับหลักฐานของรุ่น

การทดสอบแต่ละรายการระบุข้อกำหนดที่พิสูจน์ เพื่อให้วัดความครอบคลุมได้ (ADR-0017) การทดสอบอาจระบุรหัส SRS หรือระบุ ADR เมื่อยังไม่มีข้อกำหนด

## การแตกสาขาและการปล่อยรุ่น {#dso-branching}

| หัวข้อ | กฎ (ข้อเสนอ) |
| --- | --- |
| การแตกสาขา | สาขาอายุสั้นจาก `main` และ merge ผ่าน pull request |
| การทบทวน | ผู้ทบทวนอย่างน้อยหนึ่งคน และสองคนสำหรับการเปลี่ยนความมั่นคงปลอดภัย การเข้ารหัส Audit หรือ row-level security ของ `platform` |
| Commit | ทุก commit สร้างได้ และลงนาม commit บน `main` |
| รุ่น | Semantic version รุ่นหลักเปลี่ยน API แบบไม่เข้ากันได้ รุ่นรองเพิ่มความสามารถ รุ่นแก้ไขแก้ปัญหา |
| การสนับสนุนระยะยาว | สาขาสนับสนุนต่อรุ่น LTS เป็นบริการมีค่าใช้จ่ายที่ใช้โค้ดสาธารณะ (ADR-0001) |
| Hotfix | จาก tag ของรุ่น แล้วนำกลับเข้า `main` |
| การเปลี่ยนตามกฎหมาย | รุ่นกฎตามวันที่ในรุ่นปล่อยใดก็ได้ และบันทึกรุ่นระบุข้อกฎหมาย |
| Migration | expand ในรุ่นหนึ่ง และ contract ในรุ่นถัดไป (ADR-0005) |
| หลักฐานของรุ่น | SBOM, ลายเซ็น, รายงานทดสอบ, ความครอบคลุมข้อกำหนด, รายการตรวจ ASVS |

ช่วงการสนับสนุนฟรีของ Spring Boot สั้น โครงการจึงวางแผนอัปเกรดเฟรมเวิร์กภายในแต่ละช่วงการสนับสนุน (ADR-0003)

## ห่วงโซ่อุปทานซอฟต์แวร์ {#dso-supply}

รุ่นที่ปล่อยต้องให้ผู้อื่นตรวจสอบได้ (ADR-0017)

- สร้าง CycloneDX SBOM สำหรับทุก image และทุก bundle ฝั่งหน้าจอ และเผยแพร่พร้อมรุ่น
- artifact ของรุ่นต้องลงนาม Argo CD ปฏิเสธ image ที่ไม่ลงนาม และผู้ติดตั้งเองตรวจรุ่นด้วยกุญแจสาธารณะได้
- Cosign เป็นเครื่องมือลงนามที่เสนอ โดยเก็บกุญแจใน KMS DG-XC-16 บันทึกทางเลือกนี้
- base image ตรึงด้วย digest และสร้างใหม่ตามกำหนด
- dependency ตรึงด้วย lock file และดาวน์โหลดผ่าน proxy ของโครงการในไทย (ข้อเสนอ)
- งาน CI ใช้ข้อมูลรับรองอายุสั้นและรันบน runner ที่สะอาด ไม่มีขั้นตอน build ใดเข้าถึง production
- การสแกน dependency ทำกับรุ่นที่ปล่อยแล้วด้วย เพื่อแจ้งเตือนเมื่อพบช่องโหว่ใหม่หลังปล่อย
- `SECURITY.md` ระบุวิธีรายงานช่องโหว่ เป้าหมายการแก้ที่เสนอคือ 7 วันสำหรับ critical (XC-DSO-006) และ 30 วันสำหรับ high

## การปฏิบัติตามใบอนุญาต {#dso-licence}

ผลิตภัณฑ์ทั้งหมดใช้ AGPL-3.0 และ dependency ทุกตัวต้องเข้ากันได้ (ADR-0001) การตรวจใบอนุญาตทำงานใน CI

| ผล | ใบอนุญาต (ข้อเสนอ ให้ทนายความยืนยัน) | การดำเนินการ |
| --- | --- | --- |
| อนุญาต | MIT, BSD, Apache-2.0, ISC, MPL-2.0, LGPL, GPL-3.0, AGPL-3.0 | Merge |
| ทบทวน | ใบอนุญาตโอเพนซอร์สอื่น หรือใบอนุญาตฟอนต์หรือข้อมูล | ผู้ดูแลโครงการบันทึกการตัดสินใจ |
| ปฏิเสธ | GPL-2.0-only เมื่อ link, SSPL, BUSL, แพ็กเกจเชิงพาณิชย์หรือไม่มีใบอนุญาต | build ล้มเหลว |

| Dependency | ใบอนุญาตที่คาดไว้ | หมายเหตุ |
| --- | --- | --- |
| Keycloak, OpenSearch, Tink, Argo CD, Helm | Apache-2.0 | ต้องยืนยันในการตรวจ |
| OpenTofu, OpenBao, RabbitMQ | MPL-2.0 | เลือกแทนเครื่องมือ BUSL (ADR-0012) |
| EU DSS | LGPL | ไลบรารีที่ link ต้องยืนยันในการตรวจ |
| ClamAV | GPL-2.0 | รันเป็นบริการแยกและไม่ได้ link ต้องยืนยันในการตรวจ |
| Grafana, Loki, k6 | AGPL-3.0 | ใช้งานเป็นเครื่องมือ ต้องยืนยันในการตรวจ |
| TH Sarabun New | ใบอนุญาตฟอนต์ | การแจกจ่ายยังค้างอยู่ (ADR-0011) |

> [!OPEN] ใบอนุญาตของแต่ละ dependency ยังไม่ได้ตรวจสอบ (ดัชนี ADR) ตารางข้างต้นคือสิ่งที่ผู้เขียนคาดไว้ และการตรวจครั้งแรกจะมาแทน ทนายความทบทวนใบอนุญาต ข้อตกลงผู้ร่วมพัฒนา และเครื่องหมายการค้าก่อนการเผยแพร่ (ADR-0001)

กฎที่ตามมาจากใบอนุญาต:

- AGPL-3.0 ให้สิทธิ์ผู้ใช้ผ่านเครือข่ายในการได้รับซอร์สโค้ด ลิงก์ในผลิตภัณฑ์นำไปยังซอร์สของรุ่นที่รันอยู่จริง และ tag ของรุ่นเป็นส่วนหนึ่งของ build (XC-LIC-002)
- เฉพาะข้อมูลและค่าตั้งของผู้เช่าที่เป็นความลับ (ADR-0001) บริการแบบโฮสต์ไม่มี fork ส่วนตัว
- การเผยแพร่ทำจากคลังโค้ดใหม่ที่สะอาด เพื่อไม่ให้ประวัติที่มีข้อมูลผู้เช่าหรืออีเมลส่วนตัวถูกเผยแพร่
- เพิ่ม `LICENSE`, `SECURITY.md` และ `CONTRIBUTING.md` ในคลังนั้น
- คุณสมบัติด้านความมั่นคงปลอดภัย Audit และ PDPA อยู่ในรุ่นฟรี ไม่มี build flag ที่ตัดออก
- ชื่อ Fisko เป็นเครื่องหมายการค้า แยกจากใบอนุญาตของโค้ด

> [!OPEN] ต้องเลือกข้อตกลงผู้ร่วมพัฒนาก่อนรับการมีส่วนร่วมจากภายนอกครั้งแรก CLA คงความเป็นไปได้ของ dual licensing ส่วน DCO ไม่คง (ADR-0001) เจ้าของผลิตภัณฑ์ตัดสินร่วมกับทนายความ (DG-XC-17, OI-XC-12)

## ความลับ {#dso-secrets}

ไม่มีกุญแจหรือความลับในคลังโค้ด (ADR-0013)

| ที่ใด | ความลับมาจาก | การหมุน (ข้อเสนอ) |
| --- | --- | --- |
| CI | ข้อมูลรับรองแบบ federated อายุสั้น | ต่องาน |
| เซลล์แบบโฮสต์ | ที่เก็บความลับของคลาวด์ ส่งให้ pod เมื่อเริ่ม | 90 วัน และทันทีเมื่อสงสัยว่ารั่ว |
| ผู้ติดตั้งเอง | OpenBao (ADR-0012) | หน่วยงานกำหนด |
| ฐานข้อมูล | ข้อมูลรับรองแยกตามบทบาท: แอป migration relay | 90 วัน |
| Adapter | หนึ่งข้อมูลรับรองต่อผู้เช่าและต่อระบบภายนอก เท่าที่ระบบนั้นรองรับ | ตามที่ระบบกำหนด |

ความลับที่รั่วถือเป็นเหตุการณ์ด้านความมั่นคงปลอดภัย กระบวนการจัดการเหตุจะหมุนความลับ ทบทวนบันทึกการใช้กุญแจ และเริ่ม workflow เหตุละเมิดเมื่ออาจเกี่ยวข้องกับข้อมูลส่วนบุคคล (ADR-0014)
