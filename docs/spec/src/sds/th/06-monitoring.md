# การเฝ้าระวัง {#monitoring}

> [!NOTE] เครื่องมือมาจาก ADR-0017 ชื่อเมตริก วัตถุประสงค์ เงื่อนไขการแจ้งเตือน และระยะเก็บในบทนี้เป็นข้อเสนอ เจ้าของผลิตภัณฑ์ต้องยืนยันวัตถุประสงค์ก่อนให้คำมั่นแก่หน่วยงานใด

## การออกแบบ {#mon-design}

การเฝ้าระวังใช้ OpenTelemetry, Prometheus, Grafana และ Loki telemetry ติดป้ายเซลล์และผู้เช่า และไม่มีข้อมูลส่วนบุคคล (ADR-0017)

{{fig:mon-telemetry | เส้นทางของ telemetry}}

- แอป relay worker และ adapter ส่งข้อมูลผ่าน OpenTelemetry SDK ไปยัง Collector ในแต่ละเซลล์
- Collector เพิ่มป้าย `cell` และตัดแอตทริบิวต์ที่อยู่นอกรายการอนุญาต เป็นชั้นป้องกันที่สองต่อจากการทดสอบตาม ADR-0015
- telemetry ทั้งหมดอยู่ในไทย (ADR-0012) ชุดเฝ้าระวังรันรายเซลล์ และ Grafana ระดับรวมอ่านข้ามเซลล์
- Audit log เป็นบันทึกแยกที่มีกฎของตนเอง telemetry ไม่ใช้แทนได้

> [!OPEN] ADR-0017 ไม่ได้ระบุที่เก็บ trace Grafana Tempo เข้ากับชุดเครื่องมือนี้ และต้องผ่านการตรวจใบอนุญาต ผู้นำทางเทคนิคต้องเลือก (DG-XC-18) ระหว่างนี้ trace id ปรากฏในล็อกและ Problem Details จึงยังติดตามคำขอได้

ป้าย `tenant` มีในเมตริกข้างต้นที่ระบุไว้ และในล็อกและ trace ทุกรายการ ที่ 500 ผู้เช่า การติดป้ายผู้เช่าใน histogram ทุก route จะทำให้ Prometheus รับภาระเกิน รายละเอียดราย route ต่อผู้เช่าจึงมาจากล็อก ส่วนการวัดระดับเซลล์ เช่น connection pool ไม่มีผู้เช่า XC-OBS-002 กำหนดให้มีป้ายในทุกเมตริก DG-XC-23 จึงบันทึกความต่างนี้

### ล็อก {#mon-logs}

ล็อกเป็น JSON แบบมีโครงสร้าง ส่งไป Loki ทุกบรรทัดมี `timestamp`, `level`, `cell`, `tenant`, `module`, `traceId`, `event` และชุดฟิลด์ที่อยู่ในรายการอนุญาต ล็อกไม่เก็บชื่อ เลขประจำตัวประชาชน โทเค็น เนื้อหาคำขอ หรือค่า Restricted (ADR-0015)

| สายล็อก | เนื้อหา | เก็บนาน (ข้อเสนอ) |
| --- | --- | --- |
| แอป | ข้อผิดพลาด คำเตือน เหตุการณ์ธุรกิจตามรหัส | 90 วัน |
| การเข้าถึง | route สถานะ เวลา ผู้เช่า | 90 วัน |
| ความมั่นคงปลอดภัย | การเข้าสู่ระบบ การปฏิเสธ การใช้กุญแจ การให้สิทธิ์ผู้ปฏิบัติการ | 1 ปี |
| โครงสร้างพื้นฐาน | Kubernetes ฐานข้อมูล broker | 30 วัน |

### Trace {#mon-traces}

trace หนึ่งตามคำขอจาก edge ผ่านคำสั่ง และต่อข้าม outbox โดยส่ง trace context ไปกับเหตุการณ์ แอตทริบิวต์ของ span ใช้รายการอนุญาตเดียวกับล็อก การสุ่มเป็นข้อเสนอ: ข้อผิดพลาดทั้งหมด และร้อยละ 5 ของคำขอที่สำเร็จ

## ตัวชี้วัดและวัตถุประสงค์ของบริการ {#mon-slo}

ตัวเลขทั้งหมดเป็นข้อเสนอ แถวที่มีรหัสข้อกำหนดมาจาก SRS ส่วนแถวอื่นเพิ่มในบทนี้ เจ้าของผลิตภัณฑ์ต้องยืนยัน (OI-XC-01, OI-XC-02) วัตถุประสงค์วัดรายเซลล์และรายเดือนปฏิทิน และต้องเป็นจริงในช่วงสูงสุดวันที่ 30 กันยายน (XC-PER-008)

| ตัวชี้วัด | การวัด | วัตถุประสงค์ (ข้อเสนอ) | ข้อกำหนด |
| --- | --- | --- | --- |
| ความพร้อมใช้งาน | สัดส่วนเวลาให้บริการของแต่ละเดือน ไม่รวมการบำรุงรักษาที่ประกาศแล้ว | ร้อยละ 99.9 | XC-AVL-001 |
| เวลาอ่าน | เปอร์เซ็นไทล์ที่ 95 ของ API อ่าน | 500 ms | XC-PER-001 |
| เวลาคำสั่ง | เปอร์เซ็นไทล์ที่ 95 ของ API เขียน | 1 วินาที | XC-PER-002 |
| การเปลี่ยนหน้า | เปอร์เซ็นไทล์ที่ 95 จนเนื้อหาหลักแสดง | 2 วินาที | XC-PER-003 |
| เวลาค้นหา | เปอร์เซ็นไทล์ที่ 95 ของผลหน้าแรก | 1 วินาที | XC-PER-004 |
| การสร้างเอกสาร | เปอร์เซ็นไทล์ที่ 95 ของ PDF ไม่เกิน 20 หน้า | 5 วินาที | XC-PER-005 |
| ความล่าช้าของเหตุการณ์ | เปอร์เซ็นไทล์ที่ 95 จาก commit ถึงการเผยแพร่ | 5 วินาที | XC-PER-007 |
| ความล่าช้าของดัชนี | จากการบันทึกถึงดัชนีค้นหา | 60 วินาที | XC-SRC-007 |
| การเข้าสู่ระบบ | สัดส่วนที่เข้าสู่ระบบสำเร็จ ไม่รวมข้อมูลรับรองผิด | ร้อยละ 99.9 | - |
| การส่งออก | สัดส่วนการส่งที่ไม่ต้องให้เจ้าหน้าที่ดำเนินการ | ร้อยละ 99 | - |
| ความล่าช้าของการสแกน | เปอร์เซ็นไทล์ที่ 95 จากอัปโหลดถึงสะอาด | 60 วินาที | - |
| การร้อยลูกโซ่ Audit | รายการเก่าที่สุดที่ยังไม่มีแฮช | 60 วินาที | - |
| การกู้คืน | ตัวเลขในบทการติดตั้งและปรับใช้ | ตามที่เสนอในบทนั้น | XC-AVL-002, XC-AVL-003 |

ระบบภายนอกที่ล่มไม่นับรวมในวัตถุประสงค์การส่งออก และรายงานเวลานั้นแยกต่างหาก

แต่ละวัตถุประสงค์มี error budget รายเดือน เมื่อเซลล์ใช้ budget หมด การปล่อยรุ่นครั้งถัดไปของเซลล์นั้นจะรอจนแก้สาเหตุแล้ว กฎนี้เป็นข้อเสนอ

## การแจ้งเตือน {#mon-alerting}

การแจ้งเตือนออกจาก Prometheus การแจ้งเตือนต้องมีคนดำเนินการ และแต่ละรายการเชื่อมไปยัง runbook เงื่อนไขเป็นข้อเสนอ

| การแจ้งเตือน | เงื่อนไข | ระดับ | ผู้ตอบสนองคนแรก |
| --- | --- | --- | --- |
| อัตราข้อผิดพลาดของเซลล์ | อัตราข้อผิดพลาดของเซลล์เกินร้อยละ 1 นาน 5 นาที (XC-OBS-005) | Critical | ผู้ปฏิบัติการเวร |
| Budget ถูกใช้เร็ว | ใช้ error budget ที่ 14 เท่าของอัตราที่อนุญาตใน 1 ชั่วโมง | Critical | ผู้ปฏิบัติการเวร |
| เซลล์ล่ม | probe ล้มเหลวจาก 2 ตำแหน่งนาน 2 นาที | Critical | ผู้ปฏิบัติการเวร |
| ความพยายามข้ามผู้เช่า | row-level security ปฏิเสธการเขียน หรือไม่ได้ผูกผู้เช่าใน production | Critical | เวรความมั่นคงปลอดภัย |
| ลูกโซ่ Audit ขาด | การตรวจล้มเหลวครั้งใด | Critical | เวรความมั่นคงปลอดภัย, ผู้ตรวจสอบของผู้เช่า |
| การใช้กุญแจผิดกฎ | ใช้กุญแจผนึกก่อนวันกำหนด หรือการแกะกุญแจล้มเหลวพุ่งสูง | Critical | เวรความมั่นคงปลอดภัย |
| outbox ค้าง | `outbox_oldest_age` เกิน 5 นาที | High | ผู้ปฏิบัติการเวร |
| การส่งติดค้าง | `delivery_oldest_failed_age` เกิน 1 ชั่วโมง | High | ผู้ปฏิบัติการเวร และเจ้าหน้าที่ของผู้เช่าเห็นงาน |
| ฐานข้อมูลตึงตัว | pool เกินร้อยละ 80 หรือ lag ของตัวสำรองเกิน 30 วินาที | High | ผู้ปฏิบัติการเวร |
| การแย่ง ledger | เปอร์เซ็นไทล์ที่ 95 ของ `db_lock_wait` เกิน 1 วินาที | High | ผู้ปฏิบัติการเวร |
| สำรองข้อมูลล้มเหลว | ไม่มี base backup ที่สำเร็จใน 26 ชั่วโมง | High | ผู้ปฏิบัติการเวร |
| ใบรับรองใกล้หมดอายุ | ต่ำกว่า 21 วัน | Medium | ผู้ปฏิบัติการ |
| งานตกหล่น | `job_last_success` เก่ากว่าสองเท่าของกำหนด | Medium | ผู้ปฏิบัติการ |
| ฐานข้อมูลลายเซ็นของตัวสแกนเก่า | ฐานข้อมูล ClamAV เก่ากว่า 2 วัน | Medium | ผู้ปฏิบัติการ |
| สงสัยมีข้อมูลส่วนบุคคล | Collector ตัดแอตทริบิวต์ต้องห้าม | Medium | นักพัฒนาเวร |

เหตุละเมิดข้อมูลส่วนบุคคลที่สงสัยจะเริ่ม workflow เหตุละเมิดและนาฬิกา 72 ชั่วโมง (ADR-0014) ชั่วโมงของเวรยังเปิดอยู่ (DG-XC-19)

## มุมมองรายผู้เช่าและรายเซลล์ {#mon-views}

| มุมมอง | ผู้ใช้ | แสดง |
| --- | --- | --- |
| ภาพรวม | ผู้ปฏิบัติการ | ทุกเซลล์ รุ่นต่อเซลล์ วัตถุประสงค์ การแจ้งเตือนที่เปิดอยู่ |
| เซลล์ | ผู้ปฏิบัติการ | ทราฟฟิก ข้อผิดพลาด เวลา ฐานข้อมูล broker outbox ความจุเทียบช่วงสูงสุด |
| ผู้เช่า | ผู้ปฏิบัติการ ภายใต้กฎการเข้าถึงของผู้ปฏิบัติการ | ปริมาณคำขอ ข้อผิดพลาด การส่งออก พื้นที่จัดเก็บ ไม่มีข้อมูลธุรกิจ |
| ความพร้อมช่วงสูงสุด | ผู้ปฏิบัติการ เจ้าของผลิตภัณฑ์ | ภาระเทียบความจุที่ทดสอบแล้วรายเซลล์ ก่อนถึงวันที่ 30 กันยายน |
| การเชื่อมโยง | ผู้ปฏิบัติการ | สถานะของแต่ละ adapter และการส่งที่ล้มเหลว |
| ความมั่นคงปลอดภัย | ผู้ทบทวนความมั่นคงปลอดภัย | การปฏิเสธ การใช้กุญแจ การให้สิทธิ์ผู้ปฏิบัติการ สถานะลูกโซ่ |
| สถานะของหน่วยงาน | ผู้ดูแลหน่วยงาน ภายใน Fisko | สถานะบริการ สถานะการส่ง การบำรุงรักษาตามกำหนด เฉพาะผู้เช่านั้น |

telemetry ของผู้เช่าเกี่ยวข้องกับผู้เช่า มุมมองผู้เช่าของผู้ปฏิบัติการจึงแสดงเฉพาะจำนวนและสถานะ มุมมองสถานะของหน่วยงานอ่านจาก API ขนาดเล็กใน `platform` และหน่วยงานไม่ได้เข้าถึง Grafana

## ประเด็นค้าง {#mon-open}
