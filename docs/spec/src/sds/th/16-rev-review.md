# การออกแบบโมดูลทบทวนและวิเคราะห์ {#rev}

> [!NOTE] Fisko ยังไม่มีโค้ด production ต้นแบบเป็น JavaScript บนเบราว์เซอร์ที่แสดงพฤติกรรมเท่านั้น และพฤติกรรม AI ทุกอย่างในต้นแบบเป็นการจำลอง เนื้อหาทั้งบทนี้เป็นข้อเสนอเพื่อการพัฒนา แพ็กเกจ คลาส ตาราง endpoint เหตุการณ์ และชื่อการทดสอบด้านล่างยังไม่มีอยู่จริง เทคโนโลยีมาจาก ADR ที่ยอมรับแล้วใน `docs/adr/` ซึ่งบทนี้นำมาใช้และไม่เปิดประเด็นใหม่

## วัตถุประสงค์ ขอบเขต และการสอบย้อน {#rev-purpose}

<!-- covers: PDPA 39 -->

บทนี้ออกแบบโมดูลทบทวนและวิเคราะห์สำหรับ production ตอบบทเดียวกันของ SRS โมดูลนี้อยู่บนสุดของโมดูลอื่น อ่านสิ่งที่โมดูลอื่นเผยแพร่ แสดงผล และเก็บเฉพาะระเบียนของตน และยังกำหนดรูปแบบของกรอบงานเอเจนต์ที่ทุกโมดูลใช้

นอกขอบเขตของบทนี้ model gateway และแชต co-work เป็นของ `platform` และแต่ละโมดูลเป็นเจ้าของ KPI พยากรณ์ สัญญาณ เอเจนต์ และเครื่องมือของตน บทนี้ระบุเฉพาะสิ่งที่ Review ต้องการจากโมดูลเหล่านั้น

| แดชบอร์ดผู้บริหาร | REV-FR-004 ถึง REV-FR-009 | การออกแบบข้อมูล การออกแบบความมั่นคงปลอดภัย | `executive` |

## ภาพรวมการออกแบบและการตัดสินใจ {#rev-decisions}

Review เป็นโมดูลหนึ่งของ modular monolith (ADR-0002) อยู่บนสุดของลำดับการพึ่งพา จึงไม่มีโมดูลใดเรียกโมดูลนี้ การอ่านแดชบอร์ดทำบน projection ในสคีมาของตน การเขียนแตะเฉพาะระเบียนของตน ได้แก่ รายการผิดปกติ วาระ หรือค่าตั้ง

| การตัดสินใจ | เหตุผล | ทางเลือกที่ไม่ใช้ | ที่มา |
| --- | --- | --- | --- |
| ตัวรันเอเจนต์อยู่ใน `platform.ai` และ `review` เป็นผู้กำกับดูแล | Budget, Procurement และ Finance ต่างเรียกเอเจนต์ และห้ามพึ่งพา `review` ตัวรันจึงต้องอยู่ต่ำกว่าโมดูลเหล่านั้น การเขียนของการทำงานยังขัดกฎที่ Review ไม่เขียนโมดูลอื่น | ตัวรันใน `review` หลัง SPI ซึ่งทำให้เส้นทางเขียนผ่านโมดูลอ่าน; เครื่องสามชุดแบบต้นแบบ | REV-FR-036, REV-CR-001, REV-CR-002 |
| แต่ละโมดูลลงทะเบียนเอเจนต์และเครื่องมือกับตัวรัน และเครื่องมือเขียนทำเพียงเตรียมการเรียกคำสั่งปกติของโมดูล | โมดูลคงกฎของตน และขั้นที่อนุมัติผ่านการตรวจเหมือนการคลิกของคน (REV-FR-044) ต้นแบบเขียนตรง | เครื่องมือเขียนตารางโดยตรง | PLT-FR-135, REV-FR-044 |
| เครื่องมือทำงานด้วยโทเค็นของคนที่ทำรายการ ไม่ใช้บัญชีระบบ | สิทธิ์และกฎแยกหน้าที่มีผลเหมือนการคลิก (BR-REV-11) | บัญชีบริการของเอเจนต์ ซึ่งอ่านเกินสิทธิ์ผู้ใช้ | Solution Design 9.4 |
| ไม่ใช้กรอบงานเอเจนต์ของบุคคลที่สาม สถานะการทำงานและขั้นเป็น Java enum ธรรมดา | สถานะมีน้อย ต้องทดสอบทีละคู่ และไม่ควรเปลี่ยนตามไลบรารี | LangChain4j หรือไลบรารีคล้ายกันเป็นวงรอบการทำงาน | ADR-0007 |
| KPI คำนวณโดยโมดูลเจ้าของ และอ่านผ่าน `KpiSource` ใน `api` ของโมดูลนั้น | หนึ่งนิยามต่อ KPI (BR-REV-01) และ Review ไม่เก็บสูตรของโมดูลอื่น | data mart กลางที่นิยาม KPI รวม ตามที่ Solution Design วาดไว้ | REV-FR-014, ADR-0002 |
| มุมมองเป็น projection ในสคีมา `review` ป้อนด้วยเหตุการณ์และสร้างใหม่ได้ | การอ่านหนักไม่แตะตารางคำสั่ง และทุกมุมมองสร้างใหม่ได้ (REV-DR-003) | query ข้ามโมดูลสดทุกครั้งที่เปิดหน้า | XC-DAT-001, ADR-0008 |
| การตรวจจับรายการผิดปกติเป็นโค้ดกฎ ไม่ใช้โมเดล | ทุกฟีเจอร์ต้องทำงานเมื่อ AI ปิด และกฎอธิบายให้ผู้ตรวจสอบเข้าใจได้ ภายหลังโมเดลทำได้เพียงร่างคำอธิบาย | ให้โมเดลตัดสินว่าอะไรผิดปกติ | ADR-0016, REV-FR-022 |
| ตัวเลขถึงโมเดลในรูปผลของเครื่องมือเท่านั้น และโมเดลเพียงเรียบเรียง | โมเดลต้องไม่คำนวณยอดรวม (REV-FR-030) | ส่งตารางดิบแล้วให้รวมยอด | Solution Design 9.4 |
| แถบสถานะ น้ำหนัก และเกณฑ์เป็นแถว `review_setting` ที่ตรวจกับช่วงในโค้ด | ADR-0007 แยกขีดจำกัดจากค่าของหน่วยงาน และต้นแบบตรึงค่าในหน้าจอ | ตัวเลขใน React component | REV-CR-003 |
| `review` ไม่เผยแพร่ส่วนเชื่อมต่อ | ไม่มีโมดูลใดพึ่งพา ตรงตามที่ภาพรวมโมดูลคาดไว้ หน้าจอประกอบผลในเบราว์เซอร์ หน้าวันนี้จึงไม่ต้องเรียกจาก `platform` ไป `review` | ส่วนเชื่อมต่อ `HomeCards` ที่ `platform` เรียก ซึ่งทำให้เกิดวงจร | REV-CR-001 |

> [!OPEN] บทนี้ขอให้ Platform ถือ `AgentRuntime` และ `agent_run` และขอให้ Procurement เก็บเฉพาะเครื่องมือของตน ตอนนี้บท Platform บันทึกเรื่องนี้เป็นข้อเสนอใน[หัวข้อ runtime เอเจนต์ร่วม](#plt-agent-runtime) และบท Procurement เก็บเฉพาะ `ToolRegister` และเครื่องมือของตน หัวหน้าทีมเทคนิคต้องตกลงกับเจ้าของบทเหล่านั้น (DG-REV-01)

### ส่วนเชื่อมต่อที่เผยแพร่ {#rev-published}

`review` ไม่เผยแพร่ส่วนเชื่อมต่อ และไม่มีโมดูลใดพึ่งพา ซึ่งยืนยันแถวในภาพรวมโมดูล โมดูลนี้เผยแพร่เหตุการณ์เฉพาะสำหรับการแจ้งเตือนและมุมมอง audit

{{fig:rev-seq-agent-step | คนตัดสินขั้นของเอเจนต์ ซึ่งเรียกคำสั่งปกติของโมดูล}}

### คำตอบของผู้ช่วย {#rev-seq-assistant}

- gateway ใช้นโยบายของหน่วยงาน ลบข้อมูลส่วนบุคคล และบันทึกการเรียก (XC-AI-004, XC-AI-006, XC-AI-007)

- เมื่อ AI ปิดหรือผู้ให้บริการขัดข้อง ระบบแสดงผลของเครื่องมือเป็นตารางพร้อมแหล่งที่มา ผู้ใช้จึงยังได้ตัวเลข (XC-AI-003)

### การควบคุม AI {#rev-ai-security}

- การเรียกโมเดลทั้งหมดผ่าน `AiGateway` AI ปิดเป็นค่าเริ่มต้น และทุกฟีเจอร์ทำงานเมื่อปิด (ADR-0016)
- สวิตช์ AI ของหน่วยงานอยู่ในนโยบายของ gateway สวิตช์เอเจนต์ทำได้เพียงจำกัดให้แคบลง และผู้ช่วยทั่วไปต้องทำตามด้วย ผู้ช่วยทั่วไปในต้นแบบไม่มีสวิตช์ (OI-REV-03)
- `AgentProfile` เริ่มต้นปิดสำหรับทุกเอเจนต์และหน่วยงาน และเอเจนต์ที่ไม่รู้จักนับเป็นปิด ต้นแบบทำกลับกัน
- ทะเบียนเครื่องมือเป็นรายการปิดต่อเอเจนต์ ตรวจตอนเริ่มและทุกขั้น การทดสอบสถาปัตยกรรมยืนยันว่าไม่มีเครื่องมือเขียนใดเรียกคำสั่งอนุมัติ เปลี่ยนวงเงิน ลงนาม จ่ายเงิน ตัดสินผู้ชนะ หรือให้คะแนน (REV-FR-039)
- ข้อมูล Restricted ไม่เข้าสู่ผลของเครื่องมือที่ส่งให้โมเดล (XC-AI-005) ใบเสนอราคาที่ปิดผนึกและราคาที่ยังไม่ตัดสินผู้ชนะก็ไม่ส่งเช่นกัน ตามบทข้อกำหนดร่วม
- ข้อความในเอกสารถึงโมเดลในบล็อกข้อมูลที่ทำเครื่องหมายไว้เท่านั้น และเครื่องมืออ่านอย่างเดียวจำกัดผลของคำสั่งแฝง `EvalRunner` มีชุดโจมตี และหน่วยงานเปิดใช้ผู้ให้บริการที่ไม่ผ่านไม่ได้ (REV-NFR-005)
- รายการ audit ของขั้นที่อนุมัติระบุคน และเอเจนต์เป็นแหล่งที่มา ขั้นไม่ถือเป็นการตัดสินของเอเจนต์ (XC-AI-010)

### ช่องว่างที่ทราบในรุ่นนี้ {#rev-open-depth}

- ข้อมูลเชิงลึกข้ามโมดูลและวาระไม่มีต้นแบบ การออกแบบจึงหยุดที่แพ็กเกจ ตาราง และ endpoint
- ยังไม่ออกแบบกฎของตัวตรวจ เพราะ OI-REV-08 ยังเปิดอยู่
- ชนิดคอลัมน์ ดัชนี และข้อจำกัดรอบทพจนานุกรมข้อมูล
