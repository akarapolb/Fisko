# การควบคุมเอกสารและแนวทางการอ่าน {#front}

เอกสารนี้คือข้อกำหนดการออกแบบซอฟต์แวร์ (SDS) ของ Fisko ซึ่งระบุว่าระบบตอบ SRS อย่างไร และเป็นเอกสารอ้างอิงสำหรับนักพัฒนา ผู้ทดสอบ ผู้ดูแลระบบ และผู้ทบทวนด้านความมั่นคงปลอดภัย

## การควบคุมเอกสาร {#doc-control}

| รายการ | รายละเอียด |
| --- | --- |
| รหัสเอกสาร | Fisko-SDS |
| ชื่อเอกสาร | ข้อกำหนดการออกแบบซอฟต์แวร์ (SDS) ของ Fisko |
| ฉบับ | 0.1 (ร่าง) |
| วันที่ | 2026-10-30 |
| สถานะ | ร่าง: เขียนครบทุกบทแล้ว และยังไม่มีผู้ใดทบทวน |
| มาตรฐานที่ใช้ | IEEE 1016-2009 และ ISO/IEC/IEEE 42010:2022 โดยใช้แนวทาง arc42 และ C4 สำหรับสถาปัตยกรรม |
| รูปแบบการส่งมอบ | ไฟล์ HTML สองภาษาไฟล์เดียว พร้อม PDF และ Word ที่สร้างจากต้นฉบับ Markdown ชุดเดียวกัน |
| ที่เก็บต้นฉบับ | `docs/spec/src/sds/` |
| เอกสารคู่กัน | SRS ซึ่งมีข้อกำหนดที่การออกแบบนี้ตอบ |

> [!OPEN] ยังไม่ได้ระบุชื่อผู้จัดทำ ผู้ทบทวน และผู้อนุมัติ เจ้าของผลิตภัณฑ์ต้องระบุก่อนออกฉบับ 1.0

## ประวัติการแก้ไข {#revisions}

| ฉบับ | วันที่ | การเปลี่ยนแปลง |
| --- | --- | --- |
| 0.1 | 2026-10-30 | โครงสร้างเอกสาร ส่วนควบคุมเอกสาร บทนำ และมุมมองบริบท |
| 0.1 | 2026-10-30 | บทจัดซื้อจัดจ้างเป็นบทนำร่องของบทโมดูล |
| 0.1 | 2026-10-30 | เขียนครบทุกบทในฉบับร่าง และปรับ SRS กับ SDS ให้ตรงกัน ยังไม่มีผู้ใดทบทวน |

## แนวทางการอ่าน {#reading-guide}

| หากคุณเป็น | เริ่มอ่านที่ |
| --- | --- |
| นักพัฒนา | สถาปัตยกรรม แล้วจึงบทของโมดูลที่รับผิดชอบ |
| ผู้ทดสอบ | บทของโมดูล แล้วจึงข้อกำหนดใน SRS |
| ผู้ดูแลระบบ | การติดตั้งและปรับใช้ แล้วจึงการเฝ้าระวัง |
| ผู้ทบทวนด้านความมั่นคงปลอดภัย | การออกแบบส่วนกลาง แล้วจึง ADR-0013, ADR-0014 และ ADR-0015 |

ข้อความการออกแบบทุกข้อเป็นจริงตามการออกแบบที่ตัดสินใจแล้ว หรือระบุว่าเป็นข้อเสนอหรือคำถามที่เปิดอยู่ ขณะนี้ยังไม่มีโค้ดสำหรับใช้งานจริง การออกแบบจึงอธิบายระบบเป้าหมาย และอ้างต้นแบบเป็นหลักฐานของพฤติกรรมเท่านั้น
