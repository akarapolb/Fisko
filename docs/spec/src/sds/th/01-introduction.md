# บทนำ {#introduction}

## วัตถุประสงค์ {#purpose}

SDS ฉบับนี้อธิบายโครงสร้าง ข้อมูล ส่วนเชื่อมต่อ และพฤติกรรมของ Fisko อย่างละเอียดพอสำหรับการสร้าง ทดสอบ และดูแลระบบ

## ขอบเขต {#scope}

การออกแบบครอบคลุมแพลตฟอร์มกลางและโมดูลธุรกิจห้าโมดูลที่ระบุใน SRS ทั้งสำหรับบริการที่เราดูแลและหน่วยงานที่ติดตั้ง Fisko เอง

## หลักการออกแบบ {#principles}

| หลักการ | ความหมายในที่นี้ |
| --- | --- |
| ผลิตภัณฑ์ทั่วไป | ไม่มีชื่อหน่วยงานในโค้ดหรือการออกแบบ ความแตกต่างเป็นการตั้งค่าของผู้เช่าระบบ |
| กฎหมายอยู่ในโค้ด ทางเลือกอยู่ในข้อมูล | เพดานตามกฎหมายอยู่ในโค้ด และผู้เช่าระบบเลือกได้ภายในเพดานนั้น (ADR-0007) |
| แยกข้อมูลเป็นค่าเริ่มต้น | ข้อมูลของผู้เช่าระบบแยกกันด้วยฐานข้อมูลและกุญแจของตนเอง (ADR-0005, ADR-0013) |
| ย้ายที่ได้ | ใช้ส่วนเชื่อมต่อแบบเปิดเท่านั้น เพื่อให้ Fisko ทำงานบนคลาวด์หรือศูนย์ข้อมูลที่รองรับได้ (ADR-0012) |
| ทำงานได้โดยไม่มี AI | AI ปิดเป็นค่าเริ่มต้น และทุกฟังก์ชันทำงานได้โดยไม่มี AI (ADR-0016) |

## แผนที่เอกสาร {#document-map}

| บท | เนื้อหา | มุมมองตาม IEEE 1016 |
| --- | --- | --- |
| สถาปัตยกรรม | บริบท คอนเทนเนอร์ เทคโนโลยี เซลล์ | Context, composition |

| การติดตั้งและปรับใช้ | สภาพแวดล้อม การสำรองข้อมูล การกู้คืน | Deployment |

| พจนานุกรมข้อมูล | ตารางและคอลัมน์ | Information |

## การตัดสินใจ {#decisions}

ADR ใน `docs/adr/` เป็นบันทึกของการตัดสินใจแต่ละเรื่องและทางเลือกที่ไม่ใช้ เอกสารนี้นำการตัดสินใจเหล่านั้นมาใช้และไม่ทำซ้ำเหตุผล ข้อเท็จจริงที่การตัดสินใจยังต้องอาศัยอยู่ระบุไว้ในดัชนี ADR

> [!WARN] การออกแบบการติดตั้งขึ้นอยู่กับว่าหน่วยงานซื้อบริการบนคลาวด์เชิงพาณิชย์ได้หรือไม่ (ADR-0012) ซึ่งยังไม่ได้รับการยืนยัน
