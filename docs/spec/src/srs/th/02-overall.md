# ภาพรวมของระบบ {#overall}

บทนี้อธิบาย Fisko ในภาพรวม ได้แก่ ตำแหน่งของระบบ สิ่งที่ระบบทำ ผู้ใช้ สภาพแวดล้อมการทำงาน และข้อจำกัดในการออกแบบ ส่วนข้อกำหนดอยู่ในบทถัดไป

## มุมมองผลิตภัณฑ์ {#ov-perspective}

Fisko เป็น SaaS แบบหลายผู้เช่าที่ให้หน่วยงานภาครัฐของไทยมีที่เดียวสำหรับวงจรงบประมาณ การจัดซื้อจัดจ้าง การเงิน ทะเบียนโครงการ และการทบทวนและวิเคราะห์ ระบบอยู่ระหว่างผู้ใช้ของหน่วยงานและผู้ขายด้านหนึ่ง กับระบบของรัฐอีกด้านหนึ่ง

{{fig:arch-context | บริบทของระบบ Fisko}}

Fisko ไม่ได้แทนที่ระบบของรัฐ ขั้นตอนจัดซื้อจัดจ้างทางการยังอยู่ใน e-GP และตัวเลขทางการคือตัวเลขใน GFMIS และเอกสารที่ลงนามแล้ว Fisko ใช้เตรียมงาน ตรวจตามกฎ บันทึกและติดตามสิ่งที่เกิดขึ้น

| ประเด็น | ตำแหน่งของระบบ |
| --- | --- |
| รูปแบบการให้บริการ | บริการโฮสต์เดียวสำหรับหลายหน่วยงาน และติดตั้งเองได้จากโค้ดสาธารณะชุดเดียวกัน (ADR-0001, ADR-0012) |
| รูปแบบแอปพลิเคชัน | modular monolith ที่ติดตั้งเป็นชุดเดียว มีหกโมดูล (ADR-0002) |
| ผู้เช่าระบบ | แต่ละหน่วยงานเป็นผู้เช่าระบบ และจัดกลุ่มเป็นเซลล์ (ADR-0005) ส่วนราชการและรัฐวิสาหกิจต่างกันที่ค่าตั้งโปรไฟล์เท่านั้น |
| สถานะปัจจุบัน | ต้นแบบที่ทำงานบนเบราว์เซอร์อย่างเดียวแสดงพฤติกรรมของระบบ ยังไม่มีโค้ดสำหรับใช้งานจริง และการเชื่อมต่อภายนอกทั้งหมดเป็นการจำลอง |

## สรุปหน้าที่ของผลิตภัณฑ์ {#ov-functions}

ตารางนี้เป็นเพียงบทสรุป ข้อกำหนดอยู่ในบทของแต่ละโมดูล และ[ภาพรวมโมดูล](#modules)แสดงการพึ่งพากันของโมดูล

| โมดูล | หน้าที่หลัก | บท |
| --- | --- | --- |
| แพลตฟอร์ม | ผู้เช่าระบบ การเข้าสู่ระบบ บทบาท การแบ่งแยกหน้าที่ การมอบอำนาจ การตรวจสอบย้อนหลัง การแจ้งเตือน เครื่องมือ PDPA และ AI gateway | [แพลตฟอร์ม](#plt) |
| งบประมาณ | การวางแผน คำของบประมาณ รายการจัดสรร การโอนเปลี่ยนแปลง และการติดตาม | [งบประมาณ](#bgt) |
| จัดซื้อจัดจ้าง | แผน ใบขอซื้อขอจ้าง แฟ้มจัดซื้อ วิธีจัดซื้อ การบันทึกข้อมูล e-GP สัญญา การตรวจรับ และค่าปรับ | [จัดซื้อจัดจ้าง](#prc) |
| การเงิน | ใบสำคัญ การจ่ายเงิน การบันทึก GFMIS การกระทบยอด และการปิดบัญชี | [การเงิน](#fin) |
| ทะเบียนโครงการ | รหัสโครงการเดียวที่เชื่อมวงจรงบประมาณข้ามโมดูล | [ทะเบียนโครงการ](#prj) |
| ทบทวนและวิเคราะห์ | วาระ บัตรคะแนน การวิเคราะห์ข้อมูล และผู้ช่วย AI ที่เลือกใช้ได้ | [ทบทวนและวิเคราะห์](#rev) |

## กลุ่มผู้ใช้และลักษณะ {#ov-users}

กลุ่มผู้ใช้ด้านล่างมาจากบทบาทในต้นแบบ และ ADR-0006, ADR-0013 และ ADR-0014 บทของแต่ละโมดูลระบุผู้เกี่ยวข้องโดยละเอียด บทบาทเป็นข้อมูลของผู้เช่าระบบ คอลัมน์บทบาทในต้นแบบแสดงเฉพาะสิ่งที่ต้นแบบใช้ในปัจจุบัน

| กลุ่มผู้ใช้ | ใช้ Fisko เพื่อ | ลักษณะ | บทบาทในต้นแบบ |
| --- | --- | --- | --- |
| เจ้าหน้าที่หน่วยที่ขอ | จัดทำคำของบประมาณและใบขอซื้อขอจ้าง | ใช้งานเป็นครั้งคราว รู้งานของหน่วยตน แต่ไม่คุ้นกับกฎระเบียบมากนัก | `div`, `divhead` |
| เจ้าหน้าที่แผนงาน | กลั่นกรองคำขอและบริหารการจัดสรร | ใช้งานบ่อย รู้กฎงบประมาณดี | `plan` |
| เจ้าหน้าที่พัสดุ | ดำเนินการแผน แฟ้มจัดซื้อ และสัญญา | ใช้งานทุกวัน รู้กฎหมายจัดซื้อจัดจ้าง | `proc`, `prochead` |
| เจ้าหน้าที่การเงิน | ดำเนินการใบสำคัญ การจ่ายเงิน และการกระทบยอด | ใช้งานทุกวัน รู้ระเบียบการคลังและ GFMIS | `fin`, `finhead` |
| ผู้บริหารและผู้มีอำนาจอนุมัติ | อนุมัติงานและอ่านข้อมูลสรุป | ใช้งานช่วงสั้น ๆ และมักมีผู้รับมอบอำนาจทำแทน | `exec` |
| กรรมการ | แจ้งผลประโยชน์ทับซ้อน ให้คะแนนข้อเสนอ ตรวจรับงาน พิจารณาคำของบประมาณ | เจ้าหน้าที่คนใดก็ได้ที่ได้รับแต่งตั้ง จึงอาจไม่เคยได้รับการอบรม | `committee` หรือผู้ใช้ที่ยังใช้งานอยู่ |
| ผู้ตรวจสอบ | อ่านข้อมูล บันทึก และสัญญาณเตือน | อ่านอย่างเดียว ต้องการประวัติครบถ้วน | `audit` |
| ผู้ดูแลระบบของผู้เช่าระบบ | ดูแลผู้ใช้ ค่าตั้ง และการเชื่อมต่อ | เจ้าหน้าที่ไอทีหรือผู้ได้รับมอบหมายของหน่วยงาน ไม่มีสิทธิ์ในผู้เช่าระบบรายอื่น | `admin` |
| เจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล | ดูแลคำขอของเจ้าของข้อมูล เหตุละเมิด และ ROPA | เจ้าหน้าที่หน่วยงานที่มีหน้าที่ตาม PDPA | ไม่มีบทบาท |
| ผู้ขาย | ตอบ RFQ ดูสัญญาของตน ส่งใบแจ้งหนี้ | ผู้ใช้ภายนอกที่มีทักษะหลากหลาย เข้าสู่ระบบผ่านเส้นทางแยก | `vendor` แบบจำลอง |
| ประชาชน | ใช้สิทธิของเจ้าของข้อมูลในกรณีที่ผู้เช่าระบบเปิดให้ใช้ | ผู้ใช้ภายนอกที่ไม่ได้รับการอบรม ADR-0006 กำหนดให้มีเส้นทางแยก | ไม่มีบทบาท |
| เจ้าหน้าที่ผู้ให้บริการ | ดูแลบริการโฮสต์และสนับสนุนผู้เช่าระบบ | เจ้าหน้าที่ Fisko ที่อ่านข้อมูลของผู้เช่าระบบไม่ได้หากไม่มีเหตุผลที่บันทึกและได้รับอนุมัติ | ไม่มีบทบาท |

> [!OPEN] ยังไม่ทราบจำนวนผู้ใช้ในแต่ละกลุ่ม ซึ่งจำเป็นต่อแบบจำลองโหลด เจ้าของผลิตภัณฑ์ต้องประมาณจากหน่วยงานกลุ่มแรก และต้องระบุว่าประชาชนใช้ Fisko โดยตรงหรือไม่ เนื่องจากต้นแบบไม่มีบทบาทนี้

## สภาพแวดล้อมการทำงาน {#ov-environment}

โค้ดชุดเดียวทำงานได้ในสองชุดติดตั้งที่รองรับ (ADR-0012) บริการโฮสต์ใช้ชุด Enterprise ร่วมกับบริการแบบจัดการ ผู้ใช้ต้องการเพียงเว็บเบราว์เซอร์รุ่นปัจจุบัน

| ด้าน | บริการโฮสต์ | Enterprise ติดตั้งเอง | Small |
| --- | --- | --- | --- |
| ที่ตั้ง | คลาวด์เชิงพาณิชย์ในประเทศไทย ค่าเริ่มต้นคือ AWS Thailand `ap-southeast-7` สาม zone | ศูนย์ข้อมูลของหน่วยงานหรือ GDCC | เครื่องแม่ข่ายของหน่วยงาน |
| สภาพการทำงาน | Kubernetes แบบจัดการ | Kubernetes แบบ high availability | Docker Compose |
| ฐานข้อมูล | PostgreSQL แบบจัดการ | PostgreSQL | PostgreSQL |
| การส่งข้อความ | RabbitMQ | RabbitMQ | ประมวลผล outbox โดยไม่ใช้ RabbitMQ |
| การค้นหา | OpenSearch | OpenSearch | การค้นหาของ PostgreSQL ซึ่งผลภาษาไทยด้อยกว่า |
| ไฟล์ | ที่เก็บวัตถุแบบจัดการผ่าน S3 API | ผลิตภัณฑ์ที่เข้ากันได้ โดยมี Ceph RGW ในเอกสาร | ผลิตภัณฑ์ที่เข้ากันได้ |
| กุญแจและความลับ | KMS หรือ HSM | OpenBao | OpenBao |
| การยืนยันตัวตน | Keycloak | Keycloak | Keycloak |

การรองรับเบราว์เซอร์อยู่ใน XC-USA-009 เป้าหมายความพร้อมใช้งานและการกู้คืนใช้กับบริการโฮสต์ ส่วนหน่วยงานที่ติดตั้งเองกำหนดเป้าหมายของตนเอง กฎตำแหน่งข้อมูลใช้กับทุกชุดติดตั้ง (XC-PRV-016)

## ข้อจำกัดด้านการออกแบบและการพัฒนา {#ov-constraints}

การตัดสินใจเหล่านี้ระบุไว้แล้วใน `docs/adr/` SRS ถือเป็นข้อจำกัด และ SDS ออกแบบภายในกรอบนี้ การเปลี่ยนแปลงต้องมี ADR ใหม่

| การตัดสินใจ | ข้อจำกัดต่อผลิตภัณฑ์ |
| --- | --- |
| ADR-0001 | ใช้ AGPL-3.0 ทั้งผลิตภัณฑ์ ฟีเจอร์ความมั่นคงปลอดภัย การตรวจสอบ และ PDPA ยังคงฟรี และ dependency ทุกตัวต้องเข้ากันได้ |
| ADR-0002 | เป็น modular monolith ชุดเดียว โมดูลติดต่อกันผ่านส่วนเชื่อมต่อที่เผยแพร่และเหตุการณ์เท่านั้น |
| ADR-0003 | ใช้ Java 25 และ Spring Boot 4.1 ใช้ Kotlin ได้ จำนวนเงินใช้ `BigDecimal` และ REST ใช้ OpenAPI 3.1 |
| ADR-0004 | ใช้ React, TypeScript และ Vite ภาษาไทยเป็นค่าเริ่มต้น WCAG 2.1 AA เป็นเงื่อนไขการออกรุ่น และหน้าจอมาจากการตั้งค่ารายผู้เช่าระบบ |
| ADR-0005 | ใช้ PostgreSQL, row-level security และเซลล์ การเปลี่ยน schema ใช้แบบ expand and contract |
| ADR-0006 | ใช้ Keycloak สำหรับการเข้าสู่ระบบ บทบาท การแบ่งแยกหน้าที่ และการมอบอำนาจอยู่ใน `platform` และตรวจที่เซิร์ฟเวอร์ |
| ADR-0007 | ขั้นตอนตามกฎหมายอยู่ในโค้ด สายอนุมัติเป็นข้อมูลของผู้เช่าระบบ เพดานตามกฎหมายเป็นกฎที่มีวันที่มีผล และค่าตั้งของผู้เช่าระบบปรับได้ภายในเพดานเท่านั้น |
| ADR-0008 | ใช้ transactional outbox และ RabbitMQ ตัวรับเหตุการณ์เป็น idempotent และอธิบายเหตุการณ์ด้วย AsyncAPI |
| ADR-0009 | ใช้ OpenSearch ที่มีตัวตัดคำภาษาไทย และไม่นำข้อมูลชั้น Restricted เข้าดัชนี |
| ADR-0010 | ใช้ S3 API เท่านั้น สแกนด้วย ClamAV และไม่ใช้ MinIO |
| ADR-0011 | สร้าง PDF ภาษาไทยด้วย TH Sarabun New ลงนามแบบ PAdES ด้วย EU DSS และเอกสารที่ลงนามแล้วไม่เปลี่ยนแปลง |
| ADR-0012 | ใช้คลาวด์เชิงพาณิชย์ในประเทศไทย สองชุดติดตั้ง ส่วนเชื่อมต่อแบบเปิดเท่านั้น OpenTofu, Helm, Argo CD และ OpenBao และข้อมูลทั้งหมดอยู่ในประเทศไทย |
| ADR-0013 | แบ่งข้อมูลสี่ชั้น ใช้ TLS 1.3, mutual TLS และเข้ารหัสระดับฟิลด์ด้วยกุญแจรายผู้เช่าระบบ |
| ADR-0014 | หน่วยงานเป็นผู้ควบคุมข้อมูล ผู้ให้บริการโฮสต์เป็นผู้ประมวลผลข้อมูล และฟังก์ชัน PDPA อยู่ใน `platform` |
| ADR-0015 | บันทึกการใช้งานแบบ hash chain ที่ไม่มีข้อมูลส่วนบุคคล การลบทำโดยทำลายกุญแจของเจ้าของข้อมูล |
| ADR-0016 | AI ปิดเป็นค่าเริ่มต้นและอยู่หลัง gateway เดียว ทุกฟีเจอร์ทำงานได้เมื่อปิด AI และไม่ส่งข้อมูลชั้น Restricted |
| ADR-0017 | ใช้ OpenTelemetry, Playwright, k6, ASVS 5.0 ระดับ 2 และระดับ 3 สำหรับการเงินและการจ่ายเงิน มี SBOM และลงนามรุ่นที่ออก |

> [!NOTE] Fisko เป็นผลิตภัณฑ์ทั่วไป ข้อมูลเฉพาะหน่วยงานเป็นค่าตั้งหรือข้อมูลของผู้เช่าระบบ และไม่มีบทใดระบุชื่อหน่วยงานในฐานะลูกค้า

## สมมติฐานและการพึ่งพา {#ov-assumptions}

การตัดสินใจตั้งอยู่บนข้อเท็จจริงด้านล่างซึ่งยังไม่ได้ยืนยัน (`docs/adr/README.md`) แต่ละข้อต้องตรวจกับแหล่งข้อมูลต้นทางก่อนลงนามรับรอง SDS คอลัมน์สุดท้ายบอกผลกระทบหากข้อเท็จจริงไม่เป็นไปตามนั้น

| รายการ | กระทบ | ตรวจกับ | หากไม่เป็นไปตามนั้น |
| --- | --- | --- | --- |
| หน่วยงานต้องซื้อบริการคลาวด์ผ่าน GDCC หรือไม่ | ADR-0012 | DGA หรือ NT | หน่วยงานอาจสมัครใช้บริการบนคลาวด์เชิงพาณิชย์ไม่ได้ ทางเลือกสำรองคือติดตั้งเองบน GDCC |
| Claude ทำงานภายในประเทศไทยทั้งหมดได้หรือไม่ | ADR-0016 | หน้าแสดงความพร้อมของโมเดลของ AWS | prompt อาจถูกประมวลผลในต่างประเทศ ผู้เช่าระบบจึงต้องเลือกผู้ให้บริการที่โฮสต์ในประเทศไทยหรือปิด AI |
| บริการแบบจัดการที่มีในภูมิภาคที่เลือก | ADR-0012 | ผู้ให้บริการคลาวด์ | บริการโฮสต์ต้องดูแลบริการที่ขาดเองหรือใช้ภูมิภาคอื่นในประเทศไทย |

ข้อกำหนดยังตั้งอยู่บนสมมติฐานต่อไปนี้

- คาดว่าจะมีหน่วยงานประมาณ 500 แห่งภายใน 2 ถึง 3 ปี (ADR-0005)
- ทุกหน่วยงานใช้งานสูงสุดพร้อมกันเมื่อสิ้นปีงบประมาณวันที่ 30 กันยายน (ADR-0005)
- ทีมนักพัฒนาอย่างน้อย 10 คนเป็นผู้สร้างผลิตภัณฑ์ (ADR-0002)
- จนกว่ากรมบัญชีกลางจะตอบ การใช้ไฟล์ยังเป็นสมมติฐานการทำงานสำหรับ e-GP และ GFMIS
- บริการโฮสต์อยู่ภายใต้ข้อตกลงการประมวลผลข้อมูลกับแต่ละหน่วยงาน (ADR-0014)

## การจัดสรรข้อกำหนด {#ov-apportion}

ข้อกำหนดแต่ละข้ออยู่ในที่เดียว เพื่อให้ระบุครั้งเดียวและทดสอบครั้งเดียว

| ชนิดของข้อกำหนด | ตำแหน่ง |
| --- | --- |
| กฎที่ผูกพันทุกโมดูล รวมถึงเป้าหมายด้านคุณภาพ | [ข้อกำหนดร่วม](#xc) ในรูป `XC-<CAT>-nnn` |
| กฎร่วมของส่วนเชื่อมต่อภายนอก | [ส่วนเชื่อมต่อภายนอก](#interfaces) ในรูป `XC-INT-nnn` |
| ฟีเจอร์แพลตฟอร์มที่โมดูลอื่นใช้ | บท[แพลตฟอร์ม](#plt) |
| ฟีเจอร์ ข้อมูล หรือส่วนเชื่อมต่อของโมดูลเดียว | บทของโมดูลนั้น |
| กฎหมายที่กำหนดต่อกระบวนการทางการ | e-GP, GFMIS และระบบของรัฐอื่นยังเป็นผู้รับผิดชอบ Fisko บันทึกผล |
| หน้าที่ของผู้ควบคุมข้อมูล | หน่วยงาน Fisko มีเครื่องมือให้ และผู้ให้บริการโฮสต์ทำหน้าที่ผู้ประมวลผลข้อมูล |
| หน้าที่ในการให้บริการ | ผู้ให้บริการสำหรับบริการโฮสต์ และหน่วยงานเมื่อติดตั้งเอง |

> [!OPEN] ข้อกำหนดมีลำดับความสำคัญ M, S หรือ C แต่ยังไม่มีแผนการออกรุ่นที่จัดข้อกำหนดเข้าแต่ละรุ่น เจ้าของผลิตภัณฑ์ต้องตัดสินว่าข้อกำหนดใดอยู่ในรุ่นแรก และต้องยืนยันว่าแถว M เป็นขั้นต่ำสำหรับหน่วยงานแรก
