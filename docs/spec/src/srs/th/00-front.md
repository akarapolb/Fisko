# การควบคุมเอกสารและวิธีอ่าน {#front}

เอกสารนี้คือข้อกำหนดความต้องการซอฟต์แวร์ (SRS) ของ Fisko เจ้าของผลิตภัณฑ์ ผู้ทบทวนจากหน่วยงาน นักพัฒนา และผู้ทดสอบใช้เอกสารฉบับเดียวกัน และข้อกำหนดแต่ละข้อสอบย้อนกลับไปยังกฎหมาย ส่วนการออกแบบ และการทดสอบได้

## วิธีอ่านเอกสารนี้ {#how-to-read}

ทั้งสองภาษาอยู่ในไฟล์เดียวกัน ปุ่มสลับภาษาที่ส่วนหัวของหน้าเปลี่ยนระหว่างภาษาไทยกับภาษาอังกฤษได้ และการสร้างเอกสารจะหยุดเมื่อเนื้อหาสองภาษาไม่ตรงกันทีละส่วน

ข้อกำหนดแต่ละข้อคือหนึ่งแถวในตารางเจ็ดคอลัมน์ รหัสจะไม่เปลี่ยนเมื่อแก้ไขเอกสาร ผู้ทดสอบอ้างรหัสนี้ในกรณีทดสอบ และไฟล์ CSV ของข้อกำหนดที่สร้างพร้อมเอกสารใช้รหัสเดียวกัน

### รูปแบบรหัสข้อกำหนด {#id-scheme}

| รูปแบบ | ความหมาย | ตัวอย่าง |
| --- | --- | --- |
| `<MOD>-FR-nnn` | ข้อกำหนดด้านฟังก์ชันของโมดูล | `PRC-FR-001` |
| `<MOD>-NFR-nnn` | ข้อกำหนดที่ไม่ใช่ฟังก์ชันเฉพาะโมดูล | `FIN-NFR-004` |
| `<MOD>-IR-nnn` | ข้อกำหนดด้านส่วนเชื่อมต่อ | `FIN-IR-002` |
| `<MOD>-DR-nnn` | ข้อกำหนดด้านข้อมูล | `BGT-DR-001` |
| `<MOD>-CR-nnn` | ข้อจำกัดด้านการออกแบบและการพัฒนา | `PLT-CR-001` |
| `XC-<CAT>-nnn` | ข้อกำหนดระดับแพลตฟอร์มที่สร้างจากทะเบียนข้อกฎหมาย | `XC-PRV-001` |
| `UC-<MOD>-nn`, `BR-<MOD>-nn` | กรณีการใช้งานและกฎทางธุรกิจของโมดูล | `BR-PRC-03` |

รหัสโมดูลได้แก่ `PLT` แพลตฟอร์ม, `BGT` งบประมาณ, `PRC` จัดซื้อจัดจ้าง, `FIN` การเงิน, `PRJ` ทะเบียนโครงการ และ `REV` ทบทวนและวิเคราะห์

### คำอธิบายคอลัมน์ สถานะ ความสำคัญ และวิธีทวนสอบ {#legends}

| คอลัมน์ | ความหมาย |
| --- | --- |
| ID | รหัสข้อกำหนด |
| ข้อกำหนด | ข้อความที่ทดสอบได้หนึ่งข้อ ใช้คำว่า "ระบบต้อง" และระบุตัวเลขหรือกฎเมื่อมีเงื่อนไข |
| Clause | ข้อกฎหมายที่แถวนี้ตอบ ตามทะเบียนข้อกฎหมาย เช่น PPR 162 หรือ PDPA 37 ขีดหมายถึงการตัดสินใจด้านผลิตภัณฑ์ที่ไม่มีข้อกฎหมายกำหนด |
| ความสำคัญ | M จำเป็น, S ควรมี, C มีก็ได้ |
| วิธีตรวจ | T ทดสอบ, D สาธิต, I ตรวจเอกสารหรือการตั้งค่า, A วิเคราะห์ |
| สถานะ | ดูตารางถัดไป |
| Prototype | หน้าจอต้นแบบหรือการตรวจใน sweep ที่แสดงพฤติกรรมนี้ หากไม่มีใช้ขีด |

| สถานะ | ความหมาย |
| --- | --- |
| Prototyped | มีพฤติกรรมนี้ในต้นแบบและมีการตรวจใน sweep ครอบคลุม แต่ยังไม่ใช่โค้ดสำหรับใช้งานจริง |
| Partial | มีพฤติกรรมนี้ในต้นแบบบางส่วน หรือมีแต่ยังไม่มีการตรวจเฉพาะเรื่อง |
| Planned | ยังไม่มีพฤติกรรมนี้ เป็นเป้าหมายการพัฒนา |

## กฎการเขียน {#writing-rules}

- ผลิตภัณฑ์นี้เป็นแบบทั่วไป ชื่อหน่วยงานและค่าเฉพาะของหน่วยงานจะไม่ปรากฏในเอกสารนี้ แต่เป็นการตั้งค่าของผู้เช่าระบบ
- กฎที่ต่างกันได้ในแต่ละหน่วยงานให้เขียนเป็นการตั้งค่าของผู้เช่าระบบพร้อมช่วงค่าที่อนุญาต
- ตัวเลขต้องมาจากข้อกฎหมายหรือผลการวัด หรือระบุว่าเป็นข้อเสนอ
- ประเด็นที่ยังไม่ได้ข้อยุติทุกข้อเป็นคำถามที่เปิดอยู่และระบุว่าใครต้องตัดสินใจ
