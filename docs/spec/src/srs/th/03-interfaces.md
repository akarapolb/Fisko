# ส่วนเชื่อมต่อภายนอก {#interfaces}

บทนี้ครอบคลุมสิ่งที่ Fisko แสดงต่อผู้ใช้ และวิธีเชื่อมต่อกับระบบอื่น บทของแต่ละโมดูลมีข้อกำหนดส่วนเชื่อมต่อของโมดูลนั้น ส่วนแถวในบทนี้ใช้กับทุกโมดูล

## ส่วนเชื่อมต่อกับผู้ใช้ {#if-ui}

ผู้ใช้ทำงานผ่านเว็บเบราว์เซอร์ หน้าจอต้นแบบเป็นข้อกำหนดด้านภาพของส่วนหน้าจริง (ADR-0004) และกฎมาจากโค้ดใน `src/js/95b-site.js` และ style sheet ไฟล์ดังกล่าวเป็นไปตามมาตรฐานเว็บไซต์ภาครัฐ มสพร. 11-2566 ซึ่งอ้างอิง WCAG 2.1 ระดับ AA ทะเบียนข้อกฎหมายยังไม่มีรูปแบบสำหรับมาตรฐานนี้ OI-XC-09 จึงถามวิธีอ้างอิง

| ด้าน | กฎ | ข้อกำหนด |
| --- | --- | --- |
| ภาษา | ภาษาไทยก่อน และมีทั้งภาษาไทยและภาษาอังกฤษในทุกหน้าจอ เอกสารราชการที่ระบบสร้างเป็นภาษาไทย | XC-ACC-012, XC-ACC-013, XC-ACC-014, XC-ACC-015 |
| วันที่และปี | ปีพุทธศักราชในภาษาไทย ปีงบประมาณเริ่ม 1 ตุลาคม และเวลา Asia/Bangkok | XC-ACC-016, XC-ACC-017, XC-ACC-018 |
| การเข้าถึงได้ | WCAG 2.1 ระดับ AA ลิงก์ข้ามไปเนื้อหา ใช้แป้นพิมพ์ได้ และตัวอักษรไม่เล็กกว่า 12 พิกเซล | XC-ACC-001, XC-ACC-002, XC-ACC-003, XC-ACC-006 |
| การตอบสนอง | แจ้งข้อผิดพลาดที่ช่องกรอก อ่านข้อความสถานะให้ผู้ใช้ มีขั้นตรวจทานก่อนทำรายการ และย้อนกลับได้ใน 10 วินาที | XC-ACC-004, XC-ACC-005, XC-USA-005, XC-USA-006 |
| โครงหน้าจอ | หน้ารวมเดียวสำหรับโมดูล breadcrumb และส่วนท้ายที่มีชื่อผู้เช่าระบบและนโยบาย | XC-USA-008, XC-USA-002 |
| การเข้าสู่ระบบและเซสชัน | ประกาศความเป็นส่วนตัวในหน้าเข้าสู่ระบบ และออกจากระบบเมื่อไม่ใช้งานพร้อมคำเตือน | XC-PRV-001, XC-SEC-007, XC-SEC-009 |
| หน้านโยบาย | ความเป็นส่วนตัว คุกกี้ ความมั่นคงปลอดภัย เงื่อนไขเว็บไซต์ การเข้าถึงได้ และการติดต่อ | XC-USA-003 |

> [!WARN] หน้านโยบายเป็นแม่แบบที่อธิบายระบบจริง หน้าความมั่นคงปลอดภัยกล่าวถึง single sign-on การยืนยันตัวตนสองชั้น บันทึกการใช้งานที่แก้ไขไม่ได้ และการทดสอบกู้คืน ซึ่งต้นแบบยังไม่มีจริง ข้อความแต่ละข้อต้องเป็นจริงก่อนผู้เช่าระบบเริ่มใช้งาน และต้องทบทวนหน้าเหล่านี้อีกครั้ง

## ส่วนเชื่อมต่อกับซอฟต์แวร์และระบบภายนอก {#if-sw}

ไม่มีข้อมูลใดออกจากต้นแบบ ทุกแถวด้านล่างจึงเป็นการจำลองหรือยังไม่มีในปัจจุบัน ตารางระบุแต่ละระบบ และคอลัมน์ผู้รับผิดชอบระบุว่าใครต้องให้ข้อมูลที่ยังไม่ทราบ

| ระบบ | วัตถุประสงค์ | ทิศทาง | ในต้นแบบ | ผู้รับผิดชอบเรื่องที่ยังไม่ทราบ |
| --- | --- | --- | --- | --- |
| GFMIS | รายการและรายงานการเงินภาครัฐ | เข้าและออก ผ่าน Finance | ไฟล์จำลอง | กรมบัญชีกลาง |
| e-GP | ข้อมูลการจัดซื้อจัดจ้างภาครัฐ | เข้าและออก ผ่าน Procurement | ไฟล์จำลองและชุดข้อมูลสำหรับคัดลอก | กรมบัญชีกลาง |
| ThaID | การเข้าสู่ระบบของประชาชนและผู้ใช้ภายนอกอื่น | การยืนยันตัวตน ผ่าน Keycloak | ไม่มี | กรมการปกครอง |
| ไดเรกทอรีของหน่วยงาน | การเข้าสู่ระบบของเจ้าหน้าที่ | การยืนยันตัวตน OIDC หรือ SAML ผ่าน Keycloak | การเข้าสู่ระบบจำลอง | แต่ละหน่วยงาน ร่วมกับเจ้าของผลิตภัณฑ์ |
| อีเมล | การแจ้งเตือนและหนังสือ | ออก | จำลอง | เจ้าของผลิตภัณฑ์ |
| SMS | การแจ้งเตือนสั้น หาก OI-PLT-14 อนุญาตช่องทางนี้ | ออก | ไม่มี | เจ้าของผลิตภัณฑ์ |
| ผู้ให้บริการ AI | ผู้ช่วยที่เลือกใช้ได้ ปิดเป็นค่าเริ่มต้น | ออกและกลับ ผ่าน gateway | ไม่เรียกโมเดล ใช้ฟังก์ชันกฎแทน | เจ้าของผลิตภัณฑ์ จากหน้าแสดงความพร้อมของโมเดลของ AWS |
| ผู้ออกใบรับรองและบริการประทับเวลา | การลงนามและการตรวจสอบระยะยาว | ออกและกลับ | ลายมือชื่อจำลอง | เจ้าของผลิตภัณฑ์ โดยคำนึงถึงแนวทางของ ETDA (ADR-0011) |
| ระบบอื่นของหน่วยงาน | e-Budgeting, ERP, ระบบบุคลากรและเงินเดือน การบริหารโครงการ | ตามผู้เช่าระบบ | แสดงในหน้าการเชื่อมต่อ แบบจำลอง | เจ้าของผลิตภัณฑ์ |

> [!OPEN] กรมบัญชีกลางต้องให้ข้อตกลงของ GFMIS และ e-GP ได้แก่ รูปแบบไฟล์ มี API เปิดให้หน่วยงานหรือไม่ วิธีขอสิทธิ์เข้าถึง และรูปแบบข้อความ ระหว่างนี้การใช้ไฟล์ยังเป็นสมมติฐานการทำงาน บทจัดซื้อจัดจ้างระบุรายละเอียด e-GP ที่ต้องการไว้ใน[หัวข้อส่วนเชื่อมต่อ](#prc-interfaces)

> [!OPEN] กรมการปกครองต้องยืนยันเงื่อนไขการเข้าร่วม ThaID สำหรับผลิตภัณฑ์ SaaS ADR-0006 และการออกแบบการเข้าสู่ระบบรอคำตอบนี้

> [!OPEN] เจ้าของผลิตภัณฑ์ต้องยืนยันจากหน้าแสดงความพร้อมปัจจุบันของผู้ให้บริการว่าโมเดลใดทำงานภายในประเทศไทยทั้งหมด จนกว่าจะยืนยัน จะยังไม่กำหนดข้อตกลงกับผู้ให้บริการ AI (ADR-0016)

> [!OPEN] เจ้าของผลิตภัณฑ์ต้องเลือกผู้ให้บริการอีเมลและ SMS และต้องตัดสินว่าจะมีช่องทาง LINE หรือไม่ แม่แบบการแจ้งเตือนในต้นแบบมี LINE แต่ไม่มี ADR รองรับ และ ADR-0014 กำหนดให้เครื่องมือสนับสนุนอยู่ในประเทศไทย OI-PLT-14 ถือคำถามเรื่อง SMS และ LINE

> [!OPEN] แต่ละหน่วยงานต้องระบุไดเรกทอรีที่ใช้ และรองรับ OIDC หรือ SAML หรือไม่ เจ้าของผลิตภัณฑ์ต้องรวบรวมข้อมูลนี้จากหน่วยงานกลุ่มแรก เพราะยังไม่มีข้อตกลงกับไดเรกทอรีใด

แถวเหล่านี้ใช้กับระบบภายนอกทุกระบบ ผู้ให้บริการ AI อยู่ภายใต้ข้อกำหนด AI ใน[บทข้อกำหนดร่วม](#xc-ai)ด้วย และบท[แพลตฟอร์ม](#plt)ครอบคลุมบริการแจ้งเตือน
