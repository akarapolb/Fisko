# ภาพรวมโมดูล {#modules}

Fisko เป็นแอปพลิเคชันเดียวที่มีหกโมดูล (ADR-0002) บทนี้แสดงความสัมพันธ์ของโมดูล และไม่ระบุข้อกำหนดของโมดูล ซึ่งอยู่ในบทของแต่ละโมดูล

## ความสัมพันธ์ของโมดูล {#mod-relate}

เงินไหลตามเส้นทางเดียว Budget สร้างรายการจัดสรร Procurement กันเงินและก่อภาระผูกพันกับรายการนั้น แล้วส่งงานที่ตรวจรับแล้วให้ Finance จากนั้น Finance จ่ายเงินและกระทบยอดกับ GFMIS ทะเบียนโครงการเชื่อมข้อมูลเหล่านี้ด้วยรหัสโครงการเดียว โดยใช้รายการจัดสรรเป็นคีย์ร่วมและไม่เก็บสำเนาที่สอง ส่วนทบทวนและวิเคราะห์อ่านข้อมูลจากทุกส่วน และแพลตฟอร์มให้บริการทุกโมดูล

## สิ่งที่แต่ละโมดูลเป็นเจ้าของและต้องการ {#mod-owns}

| โมดูล | เป็นเจ้าของ | ต้องการจากโมดูลอื่น |
| --- | --- | --- |
| แพลตฟอร์ม (`platform`) | ผู้เช่าระบบ การเชื่อมโยงตัวตน บทบาท กฎการแบ่งแยกหน้าที่ การมอบอำนาจ บันทึกการใช้งาน การแจ้งเตือน ปฏิทินวันทำการ เครื่องมือ PDPA ไฟล์ เอกสาร ส่วนเชื่อมต่อการค้นหา และ AI gateway | ไม่ต้องการสิ่งใดจากโมดูลอื่น |
| งบประมาณ (`budget`) | ความเชื่อมโยงยุทธศาสตร์ คำของบประมาณ รายการจัดสรรและจำนวนเงิน การโอนเปลี่ยนแปลง และบัญชีคุมยอดกันเงินและภาระผูกพันของแต่ละรายการ | บริการของแพลตฟอร์ม |
| จัดซื้อจัดจ้าง (`procurement`) | แผน ใบขอซื้อขอจ้าง แฟ้มจัดซื้อ กฎเลือกวิธี สัญญา งวดงาน การตรวจรับ ค่าปรับ หลักประกัน และทะเบียนผู้ขาย | บริการของแพลตฟอร์ม จาก Budget: รายการจัดสรร วงเงินคงเหลือ การกันเงิน และการก่อภาระผูกพัน จาก Finance: ข้อเท็จจริงผ่าน SPI ที่ Finance เป็นผู้สร้าง |
| การเงิน (`finance`) | ใบสำคัญ การจ่ายเงิน การบันทึก GFMIS การกระทบยอด และการปิดบัญชี | บริการของแพลตฟอร์ม จาก Budget: รายการจัดสรรและบัญชีคุมยอด จาก Procurement: งวดงานที่ตรวจรับแล้ว ด่านตรวจก่อนจ่าย ข้อมูลสัญญาและผู้ขาย |
| ทะเบียนโครงการ (`projects`) | รหัสโครงการและการเชื่อมโยง การแลกเปลี่ยนกับระบบบริหารโครงการของหน่วยงาน และบันทึกการส่งข้อมูลออกภายนอก | บริการของแพลตฟอร์ม ข้อมูลแบบอ่านอย่างเดียวจาก Budget, Procurement และ Finance |
| ทบทวนและวิเคราะห์ (`review`) | วาระ บัตรคะแนน มุมมองการวิเคราะห์ และฟีเจอร์ผู้ช่วย AI | บริการของแพลตฟอร์ม รวมถึง AI gateway ข้อมูลแบบอ่านอย่างเดียวจากโมดูลอื่นทุกโมดูล |

> [!NOTE] โมดูลเป็นเจ้าของตารางของตนเอง และโมดูลอื่นไม่อ่านตารางนั้น รายละเอียดของแต่ละรายการข้างต้นอยู่ในบทของโมดูลนั้น

## ทิศทางการพึ่งพา {#mod-direction}

Spring Modulith ไม่ยอมรับการพึ่งพาแบบวนรอบ ทิศทางของการพึ่งพาแต่ละคู่จึงกำหนดตายตัว

- ทุกโมดูลพึ่งพา `platform` และ `platform` ไม่พึ่งพาโมดูลใด
- `procurement` และ `finance` พึ่งพา `budget` และ `budget` ไม่พึ่งพาทั้งสองโมดูล
- `finance` พึ่งพา `procurement.api` และสร้าง SPI ที่ Procurement กำหนด โดย Procurement อ่านข้อเท็จจริงของ Finance ผ่าน SPI นี้ จึงไม่เกิดการพึ่งพาแบบวนรอบ
- `projects` และ `review` พึ่งพาส่วนเชื่อมต่อที่เผยแพร่ของโมดูลอื่น มีเพียง `review` ที่พึ่งพา `projects` และไม่มีโมดูลใดพึ่งพา `review`

โมดูลยังเผยแพร่เหตุการณ์ผ่าน outbox (ADR-0008) การทำรายการข้ามโมดูล เช่น สัญญาที่ก่อภาระผูกพัน ทำในธุรกรรมเดียวได้ เพราะโมดูลอยู่ในแอปพลิเคชันเดียวกัน (ADR-0002)

> [!OPEN] บท Budget, Finance, Projects และ Review ใน SDS ยืนยันทิศทางข้างต้นแล้ว เจ้าของผลิตภัณฑ์ยังต้องยืนยันว่าหากแยกผู้ช่วย AI ออกจาก `review` ในอนาคต รายการนี้จะเปลี่ยนหรือไม่
