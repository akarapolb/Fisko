# โมดูลแพลตฟอร์ม {#plt}

## วัตถุประสงค์และขอบเขต {#plt-purpose}

Platform เก็บสิ่งที่ผลิตภัณฑ์ Fisko ทุกตัวใช้ร่วมกัน ได้แก่ tenant และค่าตั้งของหน่วยงาน การเข้าสู่ระบบ โครงสร้างองค์กรและผู้ใช้ บทบาท การแยกหน้าที่ การมอบอำนาจ สายอนุมัติ การแจ้งเตือน งานของฉัน บันทึกการใช้งาน ข้อมูลหลักที่ใช้ร่วมกัน หน้านโยบาย ความสามารถด้าน PDPA ตัวสลับระบบ ผู้ช่วย AI และการดูแลระบบ โมดูล Budget, Procurement, Finance, Projects และ Review ใช้ความสามารถเหล่านี้โดยไม่สร้างซ้ำ

ยังไม่มีโค้ดสำหรับใช้งานจริง บทนี้จึงอ่านจากโค้ดต้นแบบและชุดทดสอบ sweep ในต้นแบบ หน้าเว็บหน้าเดียวทำหน้าที่แทนเซิร์ฟเวอร์ การยืนยันตัวตน tenant และสิทธิ์ทุกอย่างจึงจำลองในเบราว์เซอร์ เมื่อเอกสารออกแบบหรือ ADR ระบุมากกว่าที่โค้ดทำ แถวนั้นจะเป็น Partial หรือ Planned และแสดงความแตกต่างไว้ในประเด็นที่ยังเปิดอยู่

| องค์ประกอบ | สถานะในต้นแบบ | หลักฐาน |
| --- | --- | --- |
| กลไกกฎแยกหน้าที่และบันทึกการพยายามที่ถูกกัน | สร้างแล้ว | Sweep walk FC1, FC2, FC4 และ FC5 |
| ออกจากระบบเมื่อไม่ใช้งาน ส่วนท้ายและหน้านโยบาย ขั้นตรวจทาน การเปิดปีงบประมาณ | สร้างแล้ว มีการตรวจเฉพาะ | Sweep ส่วน shell รอบ 65 และ 66 และ E2E walk |
| ผู้ใช้ หน่วยงาน ข้อมูลหลัก สายอนุมัติ การมอบอำนาจ หน้าบันทึกการใช้งาน | สร้างแล้ว ไม่มี action walk | Sweep แบบเปิดหน้าเท่านั้น |
| แถบระบบ ตัวเปิดระบบ พื้นที่ทำงานของฉัน รออนุมัติ ศูนย์รายการผิดปกติ | สร้างแล้ว ไม่มี action walk | Sweep ส่วน shell ตรวจเฉพาะข้อความ |
| ผู้ช่วย AI | ใช้กฎและข้อมูลตัวอย่าง ไม่เรียกโมเดล | Sweep ชุด chat ตรวจเฉพาะข้อความ |
| การเข้าสู่ระบบ MFA อีเมล LINE การส่งออกบันทึก การสำรองข้อมูล | จำลอง ไม่มีข้อมูลออกจากต้นแบบ | `54-identity.js`, `50-admin.js`, `50b-admin-depth.js` |
| การรับ tenant ใหม่ cell คำขอของเจ้าของข้อมูล ขั้นตอนเหตุละเมิด ROPA พจนานุกรมข้อมูล | ยังไม่สร้าง | ADR-0005, ADR-0014 |

เรื่องที่อยู่นอกบทนี้ ได้แก่ กฎด้านความมั่นคงปลอดภัย ประสิทธิภาพ ความพร้อมใช้งาน การเข้าถึง และภาษาที่ใช้กับทั้งผลิตภัณฑ์ (บท cross-cutting) โครงสร้างงบประมาณ แผนแม่บท คณะกรรมการพิจารณางบประมาณ และกฎ BR (BGT) ทะเบียนผู้ขาย กฎวิธีจัดซื้อ และโปรไฟล์จัดซื้อ (PRC) กฎการเงินและบัญชีธนาคาร (FIN) ทะเบียนโครงการ (PRJ) พื้นที่ผู้ดูแลระบบแสดงบางหน้าของเรื่องเหล่านี้ แต่ข้อกำหนดยังอยู่กับเจ้าของเรื่อง

## ผู้เกี่ยวข้อง {#plt-actors}

โค้ดกำหนดบทบาทไว้ 12 บทบาท ผู้ใช้หนึ่งคนมีหนึ่งบทบาทและหนึ่งหน่วยงาน รหัสบทบาทด้านล่างเป็นค่าในโค้ด

| รหัสบทบาท | ชื่อ | การใช้ Platform | กำหนดใน |
| --- | --- | --- | --- |
| `div` | สำนัก / กอง (ผู้จัดทำคำขอ) | งานของฉัน การแจ้งเตือน ข้อมูลจำกัดเฉพาะหน่วยงานตนในหลายรายการ | `00-core.js` |
| `divhead` | ผู้อำนวยการกอง | เจ้าของขั้นอนุมัติ | `41d-req-b1.js` |
| `plan` | กองแผนงาน | มอบอำนาจการกลั่นกรอง ดูแลข้อมูลหลักงบประมาณ รับมอบอำนาจ | `00-core.js` |
| `exec` | ผู้บริหาร | มอบอำนาจอนุมัติการโอน เรื่องคณะกรรมการ และการใช้จ่าย รับมอบอำนาจ | `00-core.js` |
| `fin` | การเงินและบัญชี | มอบอำนาจอนุมัติการโอน ดูสถานะการเชื่อมต่อ ดูแลราคามาตรฐาน รับมอบอำนาจ | `00-core.js` |
| `finhead` | หัวหน้าการเงิน | ดูกฎการเงินในผู้ดูแลระบบ | `66b-fin-fn1.js` |
| `proc` | เจ้าหน้าที่พัสดุ | ดูกฎและโปรไฟล์จัดซื้อในผู้ดูแลระบบ | `00-core.js` |
| `prochead` | หัวหน้าเจ้าหน้าที่พัสดุ | เหมือน `proc` | `00-core.js` |
| `committee` | กรรมการพิจารณางบประมาณ | งานของฉันและหน้าลงความเห็น | `42d-review-b3.js` |
| `audit` | ผู้ตรวจสอบ | อ่านบันทึกการใช้งาน กฎแยกหน้าที่ รายการที่ถูกกัน การเก็บรักษา และสถานะสำรองข้อมูล รับการแจ้งเมื่อปิดกฎแยกหน้าที่ | `00-core.js` |
| `admin` | ผู้ดูแลระบบ | ดูแลหน่วยงาน ผู้ใช้ ข้อมูลหลัก สายอนุมัติ กฎแยกหน้าที่ แม่แบบ และการเก็บรักษา ไม่มีอำนาจอนุมัติทางธุรกิจ | `00-core.js` |
| `vendor` | ผู้ขาย (ภายนอก) | ใช้เฉพาะพอร์ทัลผู้ขาย ไม่อยู่ในพื้นที่ทำงานและแถบระบบ | `71-t2.js` |

| ผู้เกี่ยวข้อง | หน้าที่ใน Platform |
| --- | --- |
| ผู้มอบอำนาจ | ผู้ใช้ที่มอบอำนาจอนุมัติบางส่วนให้ผู้ใช้อื่นชั่วคราว และยังคงมีอำนาจนั้นอยู่ |
| ผู้รับมอบอำนาจ | ผู้ใช้ที่ทำแทนผู้มอบภายในขอบเขตและช่วงวันที่ |
| เจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล | รับคำขอของเจ้าของข้อมูลและจัดการเหตุละเมิด ในต้นแบบไม่มีบทบาท มีเพียงช่องทางติดต่อในข้อมูลของหน่วยงาน |
| เจ้าของข้อมูลส่วนบุคคล | เจ้าหน้าที่ ผู้ขาย หรือประชาชนที่ Fisko เก็บข้อมูล |
| ผู้ให้บริการ | ดูแลบริการที่ให้เช่าใช้และเป็นผู้ประมวลผลข้อมูล (ADR-0014) ในต้นแบบไม่มีบทบาท |
| งานอัตโนมัติของระบบ | การเตือน การยกระดับ การเก็บรักษา การหมดอายุของการมอบอำนาจ |
| ผู้ช่วย AI | ผู้ช่วย Fisko และเอเจนต์ของโมดูล แสดงผ่านผู้ช่วย AI |
| ระบบภายนอก | ผู้ให้บริการบัญชีของหน่วยงาน ThaID, SMTP, LINE, SIEM |

## กฎทางธุรกิจ {#plt-rules}

กฎทางธุรกิจคือเงื่อนไขที่ข้อกำหนดหลายข้อใช้ร่วมกัน ช่องแหล่งที่มาระบุ ADR มาตรา หรือกฎในเอกสารออกแบบ ช่องสุดท้ายระบุที่ตั้งค่าและช่วงค่าที่โค้ดรับ ค่าที่ระบุว่าเก็บไว้คือมีค่าในข้อมูลแต่ไม่มีหน้าจอในต้นแบบ ช่วงค่าของรายการนั้นเป็นข้อเสนอให้เจ้าของผลิตภัณฑ์ยืนยัน

| ID | กฎ | แหล่งที่มา | ค่าตั้งและช่วงที่อนุญาต |
| --- | --- | --- | --- |
| BR-PLT-01 | ทุกการทำงานเป็นของ tenant เดียว และการอ่านหรือเขียนต้องไม่ข้าม tenant | ADR-0005 | กำหนดในโค้ด |
| BR-PLT-02 | ผู้ใช้มีหนึ่งบทบาทและหนึ่งหน่วยงาน | `83-admin-crud.js` | กำหนดในโค้ด ดู OI-PLT-05 |
