# โมดูลการเงิน {#fin}

## วัตถุประสงค์และขอบเขต {#fin-purpose}

โมดูลการเงินเป็นพื้นที่ทำงานของหน่วยงานก่อนถึง GFMIS เจ้าหน้าที่ดูแลวงเงินผูกพัน จัดทำและอนุมัติใบขอเบิก จ่ายเงิน ให้เงินยืม ออกใบเสร็จรับเงิน นำส่งเงิน ดูแลเงินนอกงบประมาณ กระทบยอด ปิดบัญชี กันเงินไว้เบิกเหลื่อมปี และตอบข้อทักท้วง ส่วนบัญชีแยกประเภททางการและการจ่ายเงินจากคลังยังอยู่ใน GFMIS (BR-FIN-01)

ขณะนี้ยังไม่มีโค้ดสำหรับใช้งานจริง บทนี้จึงอ่านจากโค้ดต้นแบบและชุดทดสอบ sweep ในกรณีที่เอกสารออกแบบกำหนดมากกว่าโค้ด แถวนั้นมีสถานะ Partial หรือ Planned และความแตกต่างอยู่ในหัวข้อประเด็นที่ยังเปิดอยู่

| ส่วนประกอบ | สถานะในต้นแบบ | หลักฐาน |
| --- | --- | --- |
| ทะเบียน ใบขอเบิก ไฟล์ GFMIS ชุดการจ่ายเงิน เงินยืม ใบเสร็จรับเงิน การนำส่งเงิน การแก้ไขจากการกระทบยอด และเงินนอกงบประมาณ | สร้างแล้ว และมีการเดินงานจริงใน sweep | Sweep walk FC1 ถึง FC7 |
| ภาษี เส้นทางการจ่าย นาฬิกาตามระเบียบ ผลต่างจากการนับเงินสด และการปิดเดือน | สร้างแล้ว แต่ไม่มีการตรวจเฉพาะ | sweep เปิดหน้าเท่านั้น |
| พยากรณ์ จำลองสถานการณ์ KPI และสัญญาณเตือน | สร้างแล้ว มีการตรวจเฉพาะการบันทึกการจำลองสถานการณ์และการคัดกรองสัญญาณเตือน | Sweep walk FC6 |
| เอเจนต์การเงิน | ใช้กฎและการคำนวณเท่านั้น ไม่เรียกโมเดล | sweep ของเอเจนต์สั่งเริ่มเอเจนต์แต่ละตัวและตรวจเฉพาะหน้าจอ |
| GFMIS ธนาคาร e-Payment และ vendor master ของกรมบัญชีกลาง | จำลอง ไม่มีข้อมูลออกนอกต้นแบบ | `85-fin-pay-crud.js`, `66f-fin-fn5.js` |

หน้าจอทั้งหมดมาจากตารางเดียวใน `66h-fin-pages.js`

| F11 | เงินนอกงบประมาณ | กองทุน แผนการใช้จ่าย และการถอนเงินฝากคลัง |

เรื่องที่อยู่นอกบทนี้: บทบาท กลไกแยกหน้าที่ การมอบอำนาจ งาน และบันทึกการใช้งาน (PLT) รายการจัดสรรและการตัดสินเรื่องการกันเงินไว้เบิกเหลื่อมปี (BGT) สัญญา การตรวจรับ ประตูเบิกจ่าย และค่าปรับ (PRC) รวมทั้งความมั่นคงปลอดภัย ความเป็นส่วนตัว ประสิทธิภาพ และการเข้าถึง (บทข้อกำหนดร่วม) เงินเดือนและค่าจ้างประจำอยู่นอก Finance โดยมาเป็นไฟล์จากระบบ HR (D-FN-03) และไม่มีการจัดทำใบขอเบิกใน Fisko

## ผู้เกี่ยวข้อง {#fin-actors}

| ผู้เกี่ยวข้อง | บทบาทในงานการเงิน | บทบาทในต้นแบบ |
| --- | --- | --- |
| เจ้าหน้าที่การเงิน | ดูแลวงเงินผูกพันและ PO จัดทำใบขอเบิก ส่งไฟล์ GFMIS จ่ายเงิน ออกใบเสร็จรับเงิน นำส่งเงิน จัดทำรายงานเงินคงเหลือประจำวัน และนำเข้ารายการเดินบัญชี | `fin` |
| หัวหน้าการเงิน | ตรวจใบขอเบิก อนุมัติภายในวงเงินของตน ตรวจการจ่ายเงินประจำวัน ลงนามงบพิสูจน์ยอดเงินฝาก ปิดงวดบัญชี ทวงเงินยืม ตอบข้อทักท้วง และดูแลทะเบียนใน F10 | `finhead` |
| ผู้มีอำนาจอนุมัติ | อนุมัติการจ่ายเงิน เงินยืม แผนเงินนอกงบประมาณ และการถอนเงินฝากคลัง โดยตรงหรือโดยการมอบอำนาจด้านการใช้จ่าย รับทราบรายงานเงินคงเหลือประจำวัน และเปิดวันหรืองวดบัญชีที่ปิดแล้วได้ | `exec` หรือผู้รับมอบอำนาจของ `exec` |
| ผู้ยืม | ผู้ใช้ทุกคน ขอเงินยืม ส่งใช้ และแก้ไขเงินยืมใน My Workspace | ทุกบทบาท |
| กรรมการเก็บรักษาเงิน | นับเงินและลงนามรายงานประจำวัน เป็นรายชื่อตามคำสั่งที่มีวันที่ ไม่มีบทบาทของตนเอง | ผู้ใช้ที่ระบุชื่อ |
| เจ้าหน้าที่แผน | อ่านหน้าจอ Finance และดำเนินการคำขอกันเงินไว้เบิกเหลื่อมปีใน Budget | `plan` |
| ผู้ตรวจสอบ | อ่านข้อมูลการเงิน และรับแจ้งการปิดงวด การเปิดงวดใหม่ และผลต่างของเงินสด | `audit` |
| ผู้ดูแลระบบ | แก้ไขกฎการเงิน ไม่มีการดำเนินงานด้านการเงิน | `admin` |
| ผู้ขาย (ภายนอก) | ขอเปลี่ยนบัญชีธนาคารของตนผ่านพอร์ทัล (PRC-IR-012) | `vendor` แบบจำลอง |
| หน่วยงานตรวจเงินแผ่นดิน (ภายนอก) | ออกข้อทักท้วงให้หน่วยงานตอบ | ไม่มีบทบาท |
| เอเจนต์ AI | Voucher Checker (AG-18) Advance Chaser (AG-19) Reconciler (AG-20) Close Assistant (AG-21) และ Disbursement Forecaster (AG-22) | ฟังก์ชันกฎ |
| ระบบภายนอก | GFMIS ธนาคาร vendor master ของกรมบัญชีกลาง และระบบ HR | จำลอง |

## กฎทางธุรกิจ {#fin-rules}

คอลัมน์ที่มาระบุข้อกฎหมายหรือกฎในเอกสารออกแบบ คอลัมน์สุดท้ายระบุจุดที่ตั้งค่าได้และช่วงค่าที่โค้ดยอมรับ ต้นแบบเก็บตัวเลขทั้งหมดด้านล่างในแบบฟอร์มเดียวที่แก้ไขได้โดยไม่มีการตรวจช่วงค่า รวมถึงตัวเลขที่มาจากระเบียบ ระบบใช้งานจริงจะแยกค่าเหล่านี้ กฎที่ระบุ Dated rule เป็นเพดานตามกฎหมายที่อยู่ในโค้ด (ADR-0007) และกฎที่ระบุว่าตั้งได้ระดับหน่วยงานเป็นค่าตั้งของหน่วยงาน ระดับของค่าเป็นป้ายกำกับของเอกสารออกแบบ ระดับ A อ่านจากระเบียบ ระดับ B มาจากคำวินิจฉัยหรือข่าวและต้องยืนยัน ระดับ C เป็นข้อเสนอของการออกแบบ

## สรุปสถานะ {#fin-status}
