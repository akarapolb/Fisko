# บทนำ {#intro}

## วัตถุประสงค์ {#purpose}

SRS ฉบับนี้ระบุว่า Fisko ต้องทำอะไร เพื่อใคร ภายใต้กฎหมายใด และมีคุณภาพระดับใด โดยไม่ระบุวิธีสร้างระบบ ซึ่งอยู่ใน SDS

## ขอบเขต {#scope}

Fisko เป็น SaaS แบบหลายผู้เช่าสำหรับหน่วยงานภาครัฐของไทย ครอบคลุมวงจรงบประมาณ การจัดซื้อจัดจ้าง การเงิน ทะเบียนโครงการ และการทบทวนและวิเคราะห์ บนแพลตฟอร์มเดียวกัน และเผยแพร่เป็นโอเพนซอร์สภายใต้ AGPL-3.0 (ADR-0001)

| โมดูล | รหัส | ครอบคลุม |
| --- | --- | --- |
| แพลตฟอร์ม | `PLT` | ผู้เช่าระบบ การยืนยันตัวตน บทบาท การแบ่งแยกหน้าที่ การมอบอำนาจ การตรวจสอบย้อนหลัง การแจ้งเตือน PDPA |
| งบประมาณ | `BGT` | การวางแผน การจัดสรร และการติดตามงบประมาณ |
| จัดซื้อจัดจ้าง | `PRC` | แผน ใบขอซื้อ รายการจัดซื้อ วิธีจัดซื้อ e-GP สัญญา และค่าปรับ |
| การเงิน | `FIN` | ใบสำคัญ การจ่ายเงิน GFMIS การกระทบยอด และการปิดบัญชี |
| ทะเบียนโครงการ | `PRJ` | ทะเบียนโครงการ |
| ทบทวนและวิเคราะห์ | `REV` | วาระ บัตรคะแนน การวิเคราะห์ข้อมูล และผู้ช่วย AI ที่เลือกใช้ได้ |

นอกขอบเขต: การแก้โค้ดเฉพาะหน่วยงาน และการดำเนินงานระบบของรัฐที่ Fisko เชื่อมต่อด้วย

> [!OPEN] รายการโมดูลเป็นไปตาม ADR-0002 เจ้าของผลิตภัณฑ์ต้องยืนยันว่ารายการนี้ครบถ้วน

## ที่มาของข้อกำหนด {#sources}

Fisko ไม่มีสัญญาจากลูกค้ารายเดียว ข้อกำหนดจึงมาจากสามแหล่ง:

| แหล่งที่มา | ใช้สำหรับ |
| --- | --- |
| กฎหมายและระเบียบ ซึ่งเก็บเป็นแถวในทะเบียนข้อกฎหมาย | สิ่งที่ผลิตภัณฑ์ต้องทำตามกฎหมาย |
| ต้นแบบที่ใช้งานได้และการทดสอบ sweep | พฤติกรรมที่แสดงและทดสอบแล้ว |
| การตัดสินใจด้านผลิตภัณฑ์ รวมถึง ADR | เรื่องอื่นทั้งหมด โดยใส่ขีดในคอลัมน์ Clause |

ทะเบียนข้อกฎหมายทำหน้าที่เหมือน TOR ในโครงการตามสัญญา แต่ละแถวคือหนึ่งข้อกฎหมายและระบุว่า SRS หรือ SDS ต้องตอบ ภาคผนวกความครอบคลุมแสดงทุกข้อที่ยังไม่ได้ตอบ

> [!LAW] เลขข้อในทะเบียนเป็นชุดเริ่มต้น ผู้เชี่ยวชาญด้านการจัดซื้อจัดจ้างและทนายความด้าน PDPA ต้องยืนยัน

## ภาพรวมเอกสาร {#overview}

| บท | เนื้อหา |
| --- | --- |
| ภาพรวมของระบบ | มุมมองผลิตภัณฑ์ กลุ่มผู้ใช้ สภาพแวดล้อม ข้อจำกัด |
| ส่วนเชื่อมต่อภายนอก | ส่วนเชื่อมต่อกับผู้ใช้ ซอฟต์แวร์ และการสื่อสาร |
